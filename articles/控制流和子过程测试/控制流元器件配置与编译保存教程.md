# 控制流元器件配置与编译保存教程

> 核对日期：2026-10-26。适用版本：`new_elements_261021` 分支、提交 `f67cf7c`。
>
> 本文讲当前 **LogicEngineConfigTool 工程工作区**的操作，不照搬旧平面画布或设计文档中的计划功能。上位机编译和保存成功，不等于已经验证设备端执行。

## 一、先明确这次要做成什么

建议在**同一个工程文件中建立四个任务**：`01_IF测试`、`02_SWITCH测试`、`03_WHILE测试`、`04_JUMP测试`。每个任务先只验证一种结构，最后一份配置里就包含 IF、SWITCH、WHILE、JUMP 四种控制流器件。

阅读顺序：第二、三节讲界面与连线；第四至七节可直接照表画图；第八节验收编译与保存结果；第十一节查错。FOR、DO_WHILE 和子过程放在第十节作为后续练习。

配套练习工程：[控制流四任务示例.json](控制流四任务示例.json)。使用当前工作区的 **打开工程**加载，随后 **另存为**自己的练习副本。四任务均已禁用；它是离线工程，不是设备运行导出。

教学图使用常量和比较器，不配置遥控、遥调或实时库写出。分支终点也用常量器件占位：它有控制入口，可以作为没有设备动作的执行步骤；输出不接消费者不是错误。

### 1.1 “可编译”要分两层

这是当前版本最重要的区别：

| 操作或状态 | 实际含义 | 本教程怎样验收 |
| --- | --- | --- |
| **保存工程**自动进行工程结构编译 | 检查工程图、参数、展开和运行元件构造；不要求已取得设备部署证据 | 这是离线练习的主要验收路径 |
| 工程状态 `project` | 工程结构编译通过，并生成对应的元件列表 | 必须达到，不能只保存成草稿 |
| 工程状态 `draft` | 当前设计尚未编译成功；文件可能仍然保存了 | 不算完成本文练习 |
| **编译检查** | 还会检查目标运行环境和部署条件 | 可能因缺设备证据被拒绝，不能与结构错误混为一谈 |
| **导出运行配置** | 独立进行运行编译并导出 | 需满足设备契约和安全证据，不是普通工程保存 |

因此，不要把“点击编译检查一定全绿”作为无设备离线练习的承诺；也不要把“文件已保存”当成结构已经编译通过。

若从源码复核，对应入口分别是 `HierarchicalCompilationService.CompileProject()`（工程结构）和 `Compile()`（含部署检查）；普通保存使用 `EditorProjectSaveService.SaveProject()`。

正常的工程保存反馈应包含：

> 工程结构编译通过；尚未验证设备部署条件，不代表可部署运行配置。

如果反馈是下面这句，仍要继续修正图或参数：

> 工程草稿已保存；运行编译未通过，不是可用运行导出。

## 二、准备工程和四个任务

1. 启动当前版本的程序，进入 **编辑器 → 可视化编辑器**。
2. 启动后的空工程通常已有一个“逻辑任务”。通过工作区的 **任务设置**，把它命名为 `01_IF测试`，扫描间隔先保留 `100ms`。
3. 返回根层，点击 **新增任务**三次，分别通过“任务设置”修改任务名称。使用工具栏的任务下拉框切换当前任务。
4. 测试期间建议取消四个任务的“启用”，防止误用于设备运行。禁用不代替结构校验；每个任务仍须完整配置。
5. 第一次保存使用新文件，例如 `控制流四任务工程.json`，不要覆盖生产工程。

当前工作区没有需要先点击的“新建工程”按钮。若已有文件正在编辑，先保存自己的工作；可以另启动一个当前版本程序做练习，或打开本文附带的练习工程。

### 2.1 添加元件和应用属性

- 从左侧器件栏拖放到当前画布；也可单击器件按钮，添加到当前视口中央。
- 普通器件双击打开属性，或右键选择 **属性（工作副本）**。
- 修改后点击 **校验并应用**。直接取消或关闭窗口，不会发布这个工作副本。
- 悬停端口可查看端口 ID、名称、类型和连接来源。下文的 ID 是端口的稳定身份，**不是端口数组下标**。
- 子过程双击是进入子画布，不是普通属性操作；要改其属性请使用右键菜单。

文中的 `A`、`B`、`判断`等名称只是便于识别的别名。手工添加时程序分配的元件 ID 可以不同，不必为了与示例数字一致而改 ID。

## 三、先学会三种连线

从**输出端按住鼠标左键，拖到输入端释放**。连接种类由释放时的修饰键和端口能力决定：

| 连接种类 | 怎样操作 | 含义 |
| --- | --- | --- |
| `Data`，纯数据 | 按住 **Shift** 拖线，且两端不是纯控制端口 | 提供计算数据，不额外指定两元件的执行先后 |
| `Control`，纯控制 | 按住 **Ctrl** 拖线；连接纯控制端口时也自动选它 | 指定下一步执行谁，不占用目标的数据来源 |
| `DataControl`，数据＋控制 | 普通拖线，且不是纯控制端口 | 同时传数据和指定执行关系 |

**本教程凡是标 `Data` 的线都按 Shift；标 `Control` 的线都按 Ctrl。** 这样不必猜编辑器会自动选择哪种。

本教程还有两条明确标为 `DataControl` 的线：**比较器 → IF**、**选择值常量 → SWITCH**，按普通拖动建立，不按 Shift 或 Ctrl。不要把本教程误读为“所有数据线都必须是纯数据线”；这两条线同时指定了明确的执行关系。

### 3.1 四条必须记住的规则

1. **一个数据输入最多一个来源。** 多条纯控制线可以进入同一个合流节点，但不能把两路分支数据都塞进同一数据输入。
2. **一个控制输出最多一个目标。** 分支内需要多个步骤就依次串联，不要从 TRUE 或同一个 Case 口拉两条执行线。
3. **普通元件只有一个静态执行后继。** 不能把普通计算器的多条数据依赖都画成不同的执行后继。
4. **`DataControl` 已包含执行关系。** 不要再为同一对元件补一条等价控制线。

多常量汇入比较器时，如果两条都用普通拖动，可能形成多个执行入口。这正是“数据线看起来都接好了，仍然编译失败”的常见原因。先照下文使用纯数据线。

## 四、任务一：IF 双分支

### 4.1 放入这些元件

| 别名 | 器件 | 关键参数 |
| --- | --- | --- |
| `A` | 常量输入 `CONST_INPUT` | `ConstValue = 1` |
| `B` | 常量输入 `CONST_INPUT` | `ConstValue = 0` |
| `比较` | 大于 `COMPARE_GT` | 比较精度 `COMPARE_PRECISION = 1` |
| `判断` | IF条件判断 `IF` | 不手填真、假分支的运行目标编号 |
| `真分支` | 常量输入 `CONST_INPUT` | `ConstValue = 100` |
| `假分支` | 常量输入 `CONST_INPUT` | `ConstValue = 200` |

常量提供的是数值，不要把常量值填成 `true` 来冒充 BOOL。本例用 `1 > 0` 得到明确的 BOOL 条件。

### 4.2 按表连五条线

| 来源 | 源输出 ID | 目标 | 目标输入 ID | 种类 |
| --- | --- | --- | --- | --- |
| A | `0: Value` | 比较 | `0: Input1` | `Data` |
| B | `0: Value` | 比较 | `1: Input2` | `Data` |
| 比较 | `0: Result` | 判断 | `0: Input` | `DataControl` |
| 判断 | `0: TRUE` | 真分支 | `0: Input` | `Control` |
| 判断 | `1: FALSE` | 假分支 | `0: Input` | `Control` |

```text
A=1 ──Data──> 大于.Input1
B=0 ──Data──> 大于.Input2
大于.Result ──DataControl──> IF.Input
IF.TRUE  ──Control──> 真分支常量100
IF.FALSE ──Control──> 假分支常量200
```

两个分支在本例中各自结束，不需要为它们再接真实设备输出。

### 4.3 检查重点

- 新版显式控制图把 TRUE、FALSE **都接上**，不要只接一个出口。
- TRUE/FALSE 是控制分支，不是 BOOL 数据输出，不能当条件数据继续接逻辑门。
- 输入 A、B 是 IF 条件的数据依赖，不要再为每个常量补一条执行线。
- 保存工程后，这个任务应形成 6 个运行元件，且不处于 `draft`。
- 将 A 改成 `0`、B 改成 `1`，再应用并保存，可以检查改参数后仍能结构编译；这不是设备运行轨迹测试。

### 4.4 以后需要公共后继时怎样合流

```text
IF.TRUE  ──Control──> 真分支步骤 ──Control──┐
IF.FALSE ──Control──> 假分支步骤 ──Control──┴─> 公共后继
```

必须真的画出两条分支尾到公共后继的控制线，不能靠数组顺序“自动合流”。公共后继若需要数据，应另有唯一、在所有到达路径上都已执行的数据来源，不能读取未必执行的兄弟分支结果。

## 五、任务二：SWITCH 多路选择

### 5.1 使用当前新建的 SWITCH

从器件栏添加的新 SWITCH 使用有序 Case 条件；不要照旧文档去填写 selector 表达式或手工维护 `ControlFlowInfo.Branches`。

新建时端口如下：

- 输入 `0: Input`：数值选择量。
- 输出 `0: 默认`：固定 default，不能删除。
- 输出 `1: EQ 0`：初始 Case；修改条件后，标签会跟着变化。

### 5.2 放入元件并改 Case

| 别名 | 器件 | 关键参数 |
| --- | --- | --- |
| `选择值` | 常量输入 | `ConstValue = 1` |
| `选择` | SWITCH | 初始 Case 设置 `Op = EQ`、`Value = 1`、`Value2 = 0` |
| `命中` | 常量输入 | `ConstValue = 100` |
| `默认` | 常量输入 | `ConstValue = 200` |

在 SWITCH 属性中修改 Case 后点击 **校验并应用**。`Value2` 虽只对 RANGE 有业务意义，也不要填 NaN 或无穷大。

### 5.3 按表连三条线

| 来源 | 源输出 ID | 目标 | 目标输入 ID | 种类 |
| --- | --- | --- | --- | --- |
| 选择值 | `0: Value` | 选择 | `0: Input` | `DataControl` |
| 选择 | `1: EQ 1` | 命中 | `0: Input` | `Control` |
| 选择 | `0: 默认` | 默认 | `0: Input` | `Control` |

```text
常量1 ──DataControl──> SWITCH.Input
SWITCH.EQ 1 ──Control──> 命中常量100
SWITCH.默认 ──Control──> 默认常量200
```

保存后这个任务应形成 4 个运行元件。把“选择值”改成 `2`，可用于后续设备仿真中的 default 场景，但本教程只验收结构编译与文件往返。

### 5.4 新增 Case 时不要漏掉这些事

- 属性窗口有 **新增接口/Case**、**删除**、**上移**；画布也有动态端口的 `+`、`−` 操作。
- Case 最多 8 条，default 不计入这 8 条；允许没有 Case，但 default 仍保留。
- 支持 `EQ / GT / GE / LT / LE / RANGE`；填写数值，不是 `x > 5` 这样的表达式。
- RANGE 必须满足 `Value < Value2`。比较容差和设备实际命中行为不能只凭上位机编译确认。
- 调整匹配顺序使用重排操作，不要通过删端口重建来“排序”。Case 的稳定端口 ID 不等于匹配顺序。
- **每个新增 Case 都接到明确目标，default 也要接。** 本教程不采用悬空 Case 的临时剔除机制。

未连接的 Case 不是“命中就结束任务”。当前工具会要求明确决定是否仅在本次运行副本中剔除它；剔除后该条件不再参与匹配，语义已经变化。未连 default 则不能当作合法结束。

## 六、任务三：WHILE 计次循环

### 6.1 当前 WHILE 没有 BOOL 条件数据输入

从当前器件栏新建的是双模式 WHILE：

- `LoopMode = 1`：计次，使用 `MaxIterations`。
- `LoopMode = 0`：读取指定实时库遥信作为条件；**不受 MaxIterations 限制**。

第一次练习选计次，不要照旧 WHILE 示例把比较器接到所谓“条件输入 0”。当前端口是：

| 方向 | ID | 名称 | 用途 |
| --- | --- | --- | --- |
| 输入 | `-1` | 执行 | 从循环外正常进入 |
| 输入 | `-2` | 回环 | 循环体唯一结构尾返回这里 |
| 输出 | `0` | 继续 | 进入循环体 |
| 输出 | `1` | 退出 | 转到循环之后 |

这里的端口 `-1/-2` 是编辑器的端口身份，不是运行 `NextID` 的终止标记。

### 6.2 放入三个元件并设置参数

| 别名 | 器件 | 设置 |
| --- | --- | --- |
| `循环` | 新建 WHILE | `LoopMode = 1`，`MaxIterations = 3`，`Link = 1`，`Dev = 2`，`Reg = 3` |
| `循环体` | 常量输入 | `ConstValue = 10` |
| `循环后` | 常量输入 | `ConstValue = 20` |

**`1/2/3` 仅用于离线结构练习，不是已确认的真实点位，不得拿这组占位值部署。** 当前实现即使选计次、运行时不读取条件遥信，工程构建仍要求 Link/Dev/Reg 已填写且非负。把它们留空或填 `-1` 会报“WHILE实时库条件未绑定”。

若要改为真实条件模式，必须选择已确认的遥信点，并另外完成停止条件、设备能力与全任务执行预算验证。

### 6.3 三条控制线，回边必须画出来

| 来源 | 源输出 ID | 目标 | 目标输入 ID | 种类 |
| --- | --- | --- | --- | --- |
| 循环 | `0: 继续` | 循环体 | `0: Input` | `Control` |
| 循环 | `1: 退出` | 循环后 | `0: Input` | `Control` |
| 循环体 | `0: Value` | 循环 | `-2: 回环` | `Control` |

**按表从上到下连：先继续，再退出，最后闭合回边。** 连接服务会校验当前候选图；在循环体和出口尚未完整时先闭合，可能立即被拒绝。

```text
WHILE.继续(0) ──Control──> 循环体.Input(0)
WHILE.退出(1) ──Control──> 循环后.Input(0)
循环体.Value(0) ──Control──> WHILE.回环(-2)
```

WHILE 是本任务的正常入口，不用为了“接满执行口”额外增加一个上游常量。循环体返回的是 **回环 `-2`**，不是正常入口 `-1`。

### 6.4 保存后的正常现象与常见错误

- 当前编译器会为计次 WHILE 插入入口复位辅助 JUMP，因此编辑图的 3 个元件可以生成 4 个运行元件。这不是多出一个用户画的 JUMP。
- 循环回边应回到循环头，不回到入口复位辅助节点，否则会破坏计数语义；辅助节点由编译器处理，不要手改。
- 每个回环口只能有一个合法结构尾。体内有 IF 时，各条继续路径先合流，再由唯一尾返回。
- 不允许器件自连；不允许从循环体中段或其他循环尾随便拉回边。
- 不能只写 `Role = loopBack` 或 `continue`，就把一条普通反向线变成合法循环。
- `MaxIterations` 合法范围为 `1..100000`，默认 `200`。取值很小也不自动证明全任务运行有界或设备可以安全停止。

## 七、任务四：JUMP 静态跳转

### 7.1 目标通过属性绑定，不从 JUMP 再拉后继线

放入三个元件：

| 别名 | 器件 | 设置 |
| --- | --- | --- |
| `起点` | 常量输入 | `ConstValue = 1` |
| `跳转` | JUMP / 静态跳转 | 通过属性绑定目标为“终点” |
| `终点` | 常量输入 | `ConstValue = 2` |

只画一条普通控制线：

| 来源 | 源输出 ID | 目标 | 目标输入 ID | 种类 |
| --- | --- | --- | --- | --- |
| 起点 | `0: Value` | 跳转 | `-1: 执行` | `Control` |

然后打开 JUMP 属性：

1. 从当前层候选器件中选择“终点”，注意核对实际器件 ID。
2. 点击 **绑定同层静态目标**。
3. 点击 **校验并应用**。

```text
起点常量 ──Control──> JUMP
                       └─ 属性静态目标：终点常量
```

**不要再画 `JUMP → 终点` 的普通控制线。** 虽然当前界面可能给 JUMP 显示共享执行输出，运行构建器仍拒绝“JUMP同时声明普通控制后继”。

保存后本任务应有 3 个运行元件；JUMP 的运行 `NextID` 应指向“终点”映射后的运行编号，而不是照抄画布编号。

### 7.2 JUMP 不是任意 goto

- 普通目标必须是**同一直接画布中的普通元件**，不是仅仅“同一任务”就可以。
- 不允许跳入兄弟子画布、子过程内部或未授权的分支/循环中段；也不要把子过程图标当普通静态目标。
- 合法与否不取决于目标编号更大还是更小，也不取决于画面上放在左边还是右边。
- 普通 JUMP 不能随意形成回跳循环；循环继续、循环退出使用结构化目标绑定。
- 若选择 **设为任务终止**，表示结束当前任务本轮，不是退出整个程序。
- 目标无效时修正绑定，不要直接改运行 `NextID` 来绕过校验。

## 八、怎样真正保存并确认不是草稿

### 8.1 正确保存顺序

1. 确认四个任务的参数都已“校验并应用”，连线种类与表格一致。
2. 点击 **保存工程**；第一次选新文件路径。也可使用 **另存为**保存工程副本。
3. 查看反馈是否为 **工程结构编译通过**，而不是“草稿已保存”。
4. 用文本编辑器检查保存文件，按下一节核对状态、任务和元件数。
5. 使用 **打开工程**重新打开该文件，依次选择四个任务，核对图、参数、WHILE 回边和 JUMP 目标。
6. 再次保存，确认仍然是工程结构编译通过。保存过后可重新打开 JSON 检查第二次结果。

保存服务本身会写同目录临时文件、读回验证后再提交。这个机制不能代替手工重开画布的验收，也不是对所有文件系统和断电情况的绝对保证。

### 8.2 JSON 检查位置

工程文件与设备运行导出不是同一种用途。当前工程序列化使用兼容外壳；重点看对应任务下的这些路径：

```text
LogicTasks[对应任务]
  ├─ Elements                       编译生成的平面元件列表
  └─ EditorMetadata
       ├─ State                     应为 "project"，不是 "draft"
       ├─ Task                      权威编辑任务，含 Canvases 及其连接
       └─ CompilationInfo
            ├─ Status               应为 "project"
            ├─ ProjectDigest        工程编译摘要
            └─ SourceMap            编辑身份与运行身份映射
```

不要只搜索顶层 `Elements` 是否非空：草稿可能保留上次的平面缓存，**非空不等于当前图编译成功**。要把 `State/Status`、当前任务内容、元件数和读回结果一起检查。

注意字段名：`CompilationInfo` 里是 **Status**，不是 `State`；`EditorMetadata` 中才是 `State`。工程编译成功仍不应被解释为 `CurrentReadiness = ready`，也不要求已经产生设备运行导出的 `RuntimeDigest`。

### 8.3 不手工维护编译结果

编译可能重排元件、重新分配运行 ID、插入 WHILE 辅助节点，并同步分支参数、数据引用和 JUMP 目标。画布 ID 与运行 ID 不同是正常现象。

不要靠修改 `NextID`、`IFPara`、`SwitchPara`、`linkdev` 中的运行跳转值或 JSON 数组顺序来“修复”错误。修正的是编辑图和设计参数，再交给软件重算。

同样，`Elements` 中同时排列真分支、假分支，不代表运行时会依次执行两个分支。

## 九、“编译检查”或运行导出仍失败怎么办

若“保存工程”已达到 `project`，但 **编译检查**仍报目标环境错误，先读具体原因，不要马上改线。

从 **目标运行环境**可以查看协议、入口、节点范围、端口寻址和目标契约。**恢复SAVE_DATA测试默认值**只是特定三节点离线预设，不会替 IF、SWITCH、WHILE、JUMP 完成设备能力确认。

新版器件运行检查还要求适用于实际目标、固件、协议及范围的证据。WHILE 另需：

- 双模式及计次入口复位能力确认；
- 全任务最坏步数、时间预算，而不只是单个循环次数；
- 与当前最终任务图及入口绑定的安全评估；
- 嵌套、重入、阻塞节点、逐步停止检查及预算耗尽停止行为的确认。

常见部署诊断包括 `target.unsupported`、`target.evidence`、`target.localTest`、`contract.invalid`、`while.safetyEvidence`。这些不能通过给字段随便填几个“已确认”或复制回归测试的合成证据来获得真实保证。

本文没有目标设备的实测证据，因而不提供伪造证据的“消错参数”。要把工程变成可导出的设备运行配置，需由实际设备和固件验证结果补齐这些条件，再使用 **导出运行配置**保存为另一个文件，不覆盖工程文件。

## 十、扩展：FOR、DO_WHILE、break/continue 与子过程

### 10.1 FOR、DO_WHILE 不等于新版 WHILE 的同义写法

当前编辑器仍有独立的 `FOR`、`DO_WHILE`，但它们保留历史契约；不要把它们当作已经与双模式 WHILE 完全统一的新器件。

| 类型 | 属性与控制出口 | 结构注意事项 |
| --- | --- | --- |
| `FOR` | FOR表达式：初始化、条件、迭代；输出 `0: Body`、`1: Exit` | 循环尾回到输入 `-2: 回环`；不能用 WHILE 的 `MaxIterations` 替代其表达式语义 |
| `DO_WHILE` | 控制流协议中的条件；输出 `0: Entry`、`1: Repeat`、`2: Exit` | Entry、Repeat 接循环体入口，Exit 接循环后继，循环尾回到 `-2` |

历史模型的普通输入是 `0: Input`，不是新版 WHILE 的执行输入 `-1`。默认空表达式或某条编译路径未报错，不代表已经证明设备端循环语义正确；建议完成四个基本任务后再单独验证这两类。

### 10.2 没有独立 BREAK、CONTINUE、LABEL、CALL、RETURN 器件

当前 break/continue 的用途由 **JUMP 的结构化循环目标**承担，而不是输入一段文字标签：

1. 在 WHILE 属性中声明循环结构成员、循环体入口、循环退出目标。
2. 将转移节点归入对应循环结构。
3. 在其属性中选择所属或祖先循环，点击 **绑定祖先循环继续**或 **绑定祖先循环退出**。
4. “继续”解析到循环头；“退出”解析到结构声明的 Exit，不是猜数组中的下一项。

跨子过程转移还须逐级控制接口授权，不能直接拉一条跨画布线。普通循环体尾的 `回环(-2)` 物理线与这种显式结构化转移不是一回事。

### 10.3 子过程的最短练习

子过程 `SUBPROCESS` 已有编辑功能，但属于**编译时展开**，不是有调用栈的函数调用。

先另建一个简单顺序链任务，避免一开始就封装 IF 或 WHILE：

```text
常量A ──Control──> 常量B ──Control──> 常量C
```

操作步骤：

1. 按 Ctrl 多选同一直接画布中的 A、B。
2. 点击 **组合为子过程**，让父层用一个子过程图标代替选区。
3. 双击图标进入子画布，检查内部与边界连接。
4. 点击 **保存并返父**，再在根层点击 **保存工程**。
5. 如需恢复平面图，选择该子过程并点击 **解散子过程**。

**保存本层／保存并返父只提交到父层，不代表已经写磁盘。** 最后仍须保存工程。

实际组合至少要选两个同层器件，并满足正常入口、完成出口等限制。选区涉及已声明 IF/SWITCH/循环结构时，须遵守完整结构归属；不能承诺任意截取循环体的一段都能组合。普通 JUMP 目标若落在选区外，也不能靠组合自动获得跨层跳转许可。

## 十一、常见错误对照表

新版工程路径通常报告 `connection.invalid`、`compile.failed` 等诊断码，不要只按旧 `CFGxxx` 文档查找。下表列的是源码校验的关键原因，**不保证界面逐字显示这些原文**：当前反馈层会隐藏部分异常详情，有时只显示 `InvalidOperationException` 和错误码。遇到这种情况，要结合任务、画布、元件定位与本表逐项排查；不能仅凭异常类型判断是哪条线错了。

| 错误关键片段 | 常见原因 | 修改方法 |
| --- | --- | --- |
| 数据类型不兼容 | 数据源和输入类型不兼容，或把控制口当数据口 | 使用正确的数据源和连接种类；IF 条件优先用比较器 BOOL 输出 |
| 数据输入只能有一个来源 | 两路分支数据接同一输入 | 保留一个数据来源；合流使用纯控制线 |
| 控制输出只能有一个目标 | 同一个出口连接多个执行目标 | 将步骤串联或添加正确的分支结构 |
| 普通器件只能有一个静态执行后继 | 把数据扇出都画成执行扇出 | 将不需要执行关系的依赖改为 Shift 纯数据线 |
| 任务必须具有唯一正常执行入口 | 多条无修饰连线制造了多个控制根 | 按表核对 Data/Control，不靠编号或摆放顺序修复 |
| 分支未绑定 | IF、WHILE 或 SWITCH default 没有明确目标 | 补齐必需控制分支，不用悬空代表结束 |
| dataControl已携带执行关系 | 同一对元件重复声明执行关系 | 保留一种执行关系 |
| 数据来源不支配消费路径 | 公共后继读取了可能未执行的分支值 | 调整生产者执行位置，或把消费放回分支内 |
| WHILE实时库条件未绑定 | 计次模式也漏了 Link/Dev/Reg | 离线填示例占位；设备测试绑定真实有效点 |
| Role不能授权回边 | 用普通入口或角色文本伪造循环回边 | 将合法唯一体尾接到该循环的 `-2: 回环` |
| JUMP不能同时声明普通控制后继 | 已绑定目标，又拉普通输出线 | 删除 JUMP 的普通后继线，保留属性目标 |
| 普通跳转只能引用同直接画布的普通器件 | 选了其他画布或子过程图标 | 改为合法同层目标，或设计明确边界接口 |
| switch.caseConfirmation | 某个 Case 没连目标 | 本教程直接接全；不要把剔除条件当正常结束 |
