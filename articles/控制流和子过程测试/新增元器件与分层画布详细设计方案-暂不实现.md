## 1. 设计目标与阅读约定

**定向实现同步（2026-10-27）：** 本轮仅静态核对日志格式、消息引用及普通元件 ID 保留相关工作树实现。`DebugMessageFormatParser` 仅接受准确 `%f`；`DebugMessageArgumentResolver` 的编辑文本仅接受 `$元件ID.稳定输出端口ID` 和 `#实时库号`，括号说明不是字面内容。`RuntimeConfigAdapter` 通过 `OutputPortMap` 输出实际 `Outputs[].Id`，不使用数组槽位；`RuntimeGraphBuilder` 保留普通源画布 ID，独立生成执行布局、目标引用及辅助节点空闲 ID。下述相关规则按此更新；其余历史核查基线和待联调结论不视为本轮验证。本轮未构建、运行回归或核验嵌入式运行时。

### 1.1 本次要完成的能力

1. 用户可以调整单个元器件的宽、高，增加端口后仍能完整显示。
2. 支持可变端口的器件可以增加、删除输入和输出，原有端口及连线保持稳定。
3. 每个器件的左上角长期显示类型；修改器件名称后仍能识别用途。
4. 同一任务内的多个器件可以编为有编号的子过程。父画布显示子过程图标，打开后在覆盖父画布的子画布中查看和编辑。左侧器件栏向当前子画布添加器件；保存、关闭后回到父画布。
5. 新增 SWITCH、循环、积分、日志和数据存储器件时，共用上述编辑能力，并保留各器件的执行规则。

### 1.2 主要用语

- **父画布、子画布**：当前层与下一层的编辑区域。子画布中的器件仍属于原来的任务。
- **子过程**：用户命名、编号的一组语句。编译时将其中器件按原执行关系接入任务；本文统一使用“子过程”这个界面名称。
- **数据端口**：传递遥信、遥测等数值的端口。
- **控制端口**：表示先执行谁、选择哪条分支、从哪里退出的端口。
- **工程原图**：用户实际编辑的器件、连线、子过程、布局和参数。
- **运行配置**：根据工程原图生成、交给下位机执行的任务和器件列表。
- **稳定编号**：器件或端口创建后保留的身份标识。改名、移动、排序时保持不变。

## 3. 总体设计与统一约束

### 3.1 三部分职责

```text
工程原图
  ├─ 任务设置
  ├─ 根画布 → 子过程图标 → 子画布 → 更深一层子过程
  ├─ 器件、端口、连线、参数和结构归属
  └─ 位置、尺寸、手工连线路径、视图倍率
           │ 取快照、校验、展开边界
           ▼
任务内的平面设计图
           │ 按目标设备能力编译、保留源 ID 并分配辅助节点 ID
           ▼
运行配置 + 运行编号到原图位置的对应表
```

1. 工程原图完整保存用户的编辑内容。普通器件继续使用现有 `ElementBase`、`InputModel`、`OutputModel` 和参数对象。
2. 一个任务可以有多个画布。根画布属于任务，每个子画布由一个子过程图标拥有；每个器件只出现在一个画布中。
3. 子过程在原任务内按原顺序执行。编译时把内部语句接入父图，保存展开前后的对应关系。子过程编号用于图形管理和诊断。
4. 当前活动画布统一接收添加、选择、删除、粘贴、连线和自动布局操作。打开子画布后，父画布保留显示并暂停交互。
5. 编译使用工程原图的独立副本。运行编号、编译后的 `NextID` 和辅助节点只进入运行配置，画布继续显示原来的器件和名称。

### 3.2 编号和顺序

| 标识 | 用途 | 何时改变 |
| --- | --- | --- |
| `TaskId` | 所属任务 | 执行明确的跨任务复制或迁移时重新绑定 |
| 器件 `Id` | 工程中的器件身份；子过程图标也占一个编辑编号 | 创建、复制时分配；移动、改名、封装、解散时保留 |
| `CanvasId` | 识别根画布或子画布，使用 GUID | 创建、复制画布时分配 |
| `SubprocessNo` | 用户可见的任务内子过程编号，如 P001 | 创建、复制或用户明确改号时分配 |
| 端口 `Id` | 同一器件同一方向内的稳定身份 | 新增时分配；删除后不自动复用 |
| `Order` | 端口或分支的显示、判断顺序 | 用户上移、下移时改变 |
| 运行 `Id` | 下位机运行节点编号 | 普通元件保持源画布 Id；仅编译辅助节点另取合法空闲 Id |

编辑编号延续当前工程的全局唯一约束，至少覆盖所有任务及隐藏子画布。分配时遍历全部画布，不能只查当前可见集合。普通元件编译后 Id 与源画布 Id 相同；执行顺序和序列化布局单独计算，不按 Id 大小排序，也不靠重编号满足目标约束。源 Id 必须位于 `NodeMin..min(NodeMax,499)`，重复或越界直接拒绝。辅助节点在合法范围内按布局顺序取最小空闲 Id，预留全部任务的源 Id（包括展开后移除的 SUBPROCESS 图标）及已生成辅助节点 Id；无空闲号时拒绝，不重编号腾位。辅助节点也计入设备限额。

`SubprocessNo` 在同一任务内唯一。创建时取最小可用正整数，显示为 P001、P002；用户可在属性中改为其他未占用编号。名称可重复，连接和归属均通过稳定身份定位。首期一个子过程拥有独立内容，复制后各自编辑；公共函数定义、多处共享调用和递归调用留作后续扩展。

### 3.3 连线的一致记录

新工程用每个画布的 `Connections` 集合作为连线的统一记录。每条线包含连接 ID、数据/控制类别、两端器件及端口、控制角色和手工路径点。类别 `Kind` 允许 `data`、`control`、`dataControl`，分别表示传值、传递执行关系、同时承担二者。一条复合连线在界面和工程中只保存一次，分析时分别生成数据依赖和控制关系；一次控制到达只执行目标一次。

类型描述表增加 `ExecutionEffect=pure|effectful`，区分纯计算与会写库、累计、打印、保存等有副作用器件。可执行普通器件统一具有编辑用控制入口和顺序后继。端点增加 `PortRole=numeric|executionIn|executionOut`，省略时为 numeric；逻辑执行口使用角色定位，不占用数值口 ID，不导出为额外 Inputs/Outputs。旧复合口连线转换为 dataControl，控制投影关联该器件的逻辑执行入口、后继，数值投影仍指向原端口。

例如 SAVE_DATA 到 ALGO_INTEGRAL 的透传连接可以同时表示先恢复、后累计。迁移、组合和展开均保留同一连接的两种作用；不得另加一条重复执行边。有副作用器件必须具备唯一明确的执行安排，缺少时允许保存草稿、禁止运行导出。纯数据子过程只保留数据依赖，不强加顺序控制链。

- 数据输入一口一源；数据输出可以连接多个合法目标。
- 一个控制输出默认只有一个目标；选择分支由多个明确的输出口表达。
- 结构汇合和子过程正常出口可以接受多条控制边。它们使用控制连接集合记录，保留全部来路。
- `InputModel.SourceElemId/SourcePortId`、`OutputModel.TargetPorts` 在需要调用旧接口时由连接集合生成兼容视图；用户操作统一修改连接集合。
- 同一条边的两端和分支目标在一次操作内更新。更新不完整时回滚，避免一端已删、另一端残留。
- 画布之间的连线通过子过程接口转接；连线编辑只展示当前画布中的端点。

### 3.4 编辑操作和失败处理

全文采用以下状态与门槛，器件表、实施出口及验收均不得另设冲突口径：

- **结构错误**：损坏引用、非法拓扑、父子关系不明、重复结构身份，阻止工程事务提交。显式 unbound 诊断不等于损坏的有效引用。
- **运行就绪错误**：未接输入、未选点位、参数未完成、设备能力未确认、未绑定合法目标，允许保存带诊断的 draft；禁止生成 ready 和运行导出。
- **设备运行失败**：属于运行时或联调问题，不改变工程是否可保存。
- **运行导出**：每次重新完整校验与编译，不使用旧平面缓存或上次授权。禁止通过删除字段、静默省略参数、设备缺省将草稿变成可运行配置。
- **唯一例外**：SWITCH 未绑定 Case 可在本次导出逐项确认后仅从运行副本剔除；原工程条件、CaseKey、PortId、Order 和诊断保留。未确认、取消、default 未绑定、其他未绑定引用或结构错误仍阻止导出。确认不跨次保存；文案说明原本可能命中该 Case 的输入将继续匹配后续 Case 或 default，不等价于结束本轮。此例外不把原工程自动标成 ready。

新增端口、删除端口、组合子过程、解散、复制、应用子画布修改等操作，都按“准备候选结果 → 校验 → 一次应用”执行。需要确认时先显示影响清单；用户取消或校验失败，原图保持原样。

为新增操作提供统一的 `GraphEditTransaction` 和编辑历史记录。拖动尺寸从按下到释放记一次操作；一次组合或删除记一次操作。首期撤销至少覆盖本次新增的操作，旧命令接入情况应在界面能力和测试中逐项说明。

## 4. 元器件尺寸与固定类型区

### 4.1 界面分区

器件从上到下划为类型区、名称及编号区、端口区：

1. 左上角固定类型区：第一行“类型：时间积分”，第二行 `Type: ALGO_INTEGRAL`。内容来自类型描述表，只读。
2. 名称和编号区：例如“名称：累计电量”“编号：E23”。名称可编辑，编号单独展示。
3. 端口区：左侧输入、右侧输出；显示方向、稳定端口编号、名称以及可用的单位。控制端口显示“执行、完成、Case、默认”等语义。
4. 右上角可显示诊断标记；悬停查看完整原因，双击诊断定位到实际器件。

中文类型、英文 Type 和实例名称分别绑定。`Name` 不参与判断器件类型。`ElementDescriptorCatalog` 统一提供中文类型名、协议 Type、分类、默认名称及端口能力，供工具栏、属性窗口、画布和 SVG 导出共用。

未知 Type 显示“未知类型：原始标识”，保留其原始数据并给出诊断。已知类型即使名称被改为空或其他业务名称，类型区仍完整显示。长类型名称换行，类型区随内容增高。

### 4.2 尺寸调整

选中器件后，在右边、下边及右下角显示调整手柄；属性窗口同时提供宽、高和“适应内容”。拖动只改变器件占用的矩形，画布缩放继续用于放大、缩小整个视图。

拖动期间按当前画布倍率换算鼠标位移，持续更新器件外框和连线端点。松开鼠标提交一次编辑操作；按 Esc 恢复拖动前的尺寸。最小尺寸由标题、名称和两侧端口内容共同计算，缩小时停在最小尺寸并提示“已达到容纳当前内容的最小尺寸”。

```text
┌──────────────────────────────────────────────┐
│ 类型：子过程                                 │
│ Type: SUBPROCESS                             │
│ P003：母线运行检查                            │
│ 数据输入0：电压/V          数据输出0：状态     │
│ 数据输入2：电流/A          控制输出0：完成     │
└──────────────────────────────────────────────┘
```

该示意图中的输入端口 1 已删除，因此保留端口 0、2。显示顺序相邻，稳定编号继续保留。

### 4.3 布局计算与尺寸字段

复用 `ElementDisplayInfo`：`SizeMode=auto|manual`、`Width`、`Height`、`FontSize`。尺寸单位采用 WPF 的 DIP，即与系统显示比例无关的逻辑像素。自动模式由内容计算尺寸；手动模式保存用户请求的宽、高，实际布局同时满足内容下限。

布局服务先测量类型、名称和每个端口的文本，再计算：

```text
最小宽度 = max(类型区宽度, 名称区宽度,
               左侧最长端口宽度 + 中间间距 + 右侧最长端口宽度)
           + 左右内边距
最小高度 = 类型区高度 + 名称区高度
           + Σ各同行 max(输入测量高, 输出测量高, 最小行高)
           + 区域间距及上下内边距
实际宽度 = max(最小宽度, 手动请求宽度)
实际高度 = max(最小高度, 手动请求高度)
```

初始样式采用 12 DIP 字号、6 DIP 内边距、端口行高至少 24 DIP、两列间距至少 16 DIP；这些值集中在样式和布局常量中，允许后续按人工验收微调。端口文本按可用列宽测量换行，同行左右取较高行高，不能让一侧文字盖住另一侧。

用户增加端口、改成长名称或提高字号后，实际尺寸可自动增大。删除端口后自动模式回到内容尺寸；手动模式保留请求尺寸，用户可继续拖小或点击“适应内容”。恢复自动模式时清除手动请求尺寸。非法、负值、NaN、Infinity 和过大尺寸在属性校验时拒绝；导入异常尺寸时采用自动模式并显示恢复诊断。

### 4.4 端点、命中和导出共用布局

`ElementLayoutService` 输出一个 `ElementLayoutResult`，包含主体矩形、类型/名称区矩形、各端口锚点、完整可见边界和最小尺寸。

控件绘制、连线、命中、框选、避障、SVG 和编译投影共用端点键：`NodeKind + ElementId/BoundaryCanvasId + Direction + PortRole + 可选 PortId`。普通数据口必须有稳定非负 ID；executionIn/executionOut 不强制数值 ID；SWITCH Case 和可编辑边界接口仍须稳定身份。现有 GraphConnectionService 的 -1/-2 保留编号只用于兼容转换，不与新版角色规则混用。尺寸变化不改变身份和连接。

一次尺寸更新按下列顺序执行：

1. 更新显示参数，标记该器件布局失效。
2. 下一次界面布局时重新测量和生成端口锚点。
3. 按旧、新边界刷新相关连线及避障缓存。
4. 更新框选边界、画布可滚动范围及导出范围。

拖动中合并重复刷新，避免一次鼠标移动触发全图重建。视图坐标先转换到活动画布的逻辑坐标，再计算尺寸变化，避免在 50%、200% 倍率下放大或缩小错误。手柄区域拦截移动/连线操作，释放鼠标捕获后清除拖动状态。

### 4.5 保存和兼容

`Display` 随普通器件、子过程图标、深拷贝及 JSON 往返保存。旧配置缺少 `Display` 时使用自动模式。打开后恢复名称、端口和尺寸，再生成连线，避免先按固定宽度画线。

布局参数只影响工程展示。新旧设备运行配置的端口、运算参数及 `NextID` 不因改变尺寸而变化；验收时比较调整尺寸前后的运行结果。

## 5. 可变输入、输出端口

### 5.1 按器件能力开放增减

所有器件使用同一套端口增减服务，具体允许改哪一组由类型描述表定义：

| 器件或接口 | 输入数量 | 输出数量 | 本次开放的操作 |
| --- | --- | --- | --- |
| SWITCH | 一个选择值输入（`Command`），另有编辑用控制入口 | 设备侧无数据输出口，分支由 `nextId` 跳转；工程侧表达为固定 default 加 0～8 个 Case 出口 | 增删 Case、调整 Case 顺序；default 保留 |
| 子过程 | 一个可选控制入口；数据接口按实际需要定义 | 一个可选正常完成口；数据接口和显式转移口按需要定义 | 增删数据输入、数据输出及未使用的接口 |
| ALGO_INTEGRAL | 一个遥测输入，必须连接 | 一个累计量输出 | 固定端口，持久化在属性中配置 |
| SAVE_DATA | 一个透传输入（组态必须完成连线） | 一个透传输出，等于输入值 | 固定端口；存储点位在参数中配置 |
| DEBUG_PRINT | 源选择输入 0 必接；触发输入 1 可悬空 | 一个透传输出，等于输入 0 | 固定端口；消息实参数量可变，最多 8 个 |
| WHILE | 无数据端口；编辑用控制入口；依赖新进入复位的计次模式须输出最终入口 SourceElemId（控制元数据） | 继续、退出两个控制输出 | 显式模式与次数，协议不足阻止相关导出 |
| JUMP | 无端口；编辑用控制入口和目标关系 | 无端口；固定跳转目标 | 通过目标选择器修改目标 |

运行侧端口数量以各器件文档为准：SWITCH 无数据输出口、WHILE 无数据端口、JUMP 无端口。工程原图仍按上表画出编辑端口，编译适配器只导出目标协议接受的字段，不能为 WHILE 补一个数据输入，也不能为 SWITCH 补数据输出。

本次“可变端口”先落实在 SWITCH 分支和子过程的两侧数据接口。积分、单点存储等器件保持各自方案规定的端口数量。后续新增真正的多输入或多输出器件时，在类型描述表中声明能力并提供运行转换，无需再次改造画布交互。

普通数据口沿用现有遥信/遥测类型和连接校验。控制边单独标记；编辑用控制入口可以存在于工程原图中，下发时按运行协议转换，不能因此给积分或 WHILE 多导出一个数值输入。

### 5.2 端口定义与关联身份

在现有输入、输出模型上补足以下信息，已有同义字段优先复用：

- `Id`：稳定整数编号；输入和输出各自分配，允许两个方向都使用 0。
- `Order`：显示顺序，与 `Id` 分开。
- `Kind`：数据、控制或复合，取值及逻辑执行口见第 3.3 节。
- `GroupKey`：属于哪组可变端口，例如 `cases`、`dataInputs`。
- `Name`、数据类型、单位：界面和校验所用信息。
- `IsRequired`：是否必须连接。
- `CanDelete`：固定口和结构生成口为 false。
- 器件级 `NextInputPortId/NextOutputPortId`：下次可分配编号；加载旧文件时从该方向最大 ID 加一建立。

子画布 `BoundaryPorts` 是边界接口权威来源；画布持久化 `NextBoundaryInputPortId/NextBoundaryOutputPortId` 两方向高水位。删除、调序、撤销不得降低高水位，不能仅凭重开后现存最大 ID 重建而复用已删身份。父图标计数器仅为派生兼容值。复制保留内部端口身份及对应高水位，为器件、画布身份另建映射。

`PortGroupDescriptor` 定义每组最少、最多数量、允许的数据类型、创建默认值及删除前关联检查。数量指组内现存端口个数，不能使用最大端口 ID 推算。达到数量下限、上限时禁用相应按钮并显示原因。首期子过程数据输入、数据输出分别允许 0～128 个，控制口另外统计；SWITCH Case 为 0～8 个。端口 ID 采用非负 Int32，耗尽时拒绝新增且保留原图。

SWITCH 的分支保存稳定 `CaseKey`、输出 `PortId` 和 `Order`，条件及目标跟随同一个 `CaseKey`。子过程的数据接口保存稳定端口 ID；内部映射也引用同一 ID。删除一个前排端口，后面的端口只改变显示位置。

### 5.3 增加端口

1. 属性窗口提供“输入端口”“输出端口”页，列出编号、名称、类型、连接情况；可变组显示“增加”按钮。画布右键菜单提供同名入口。
2. 选定允许的组、名称和数据类型；若组只有一种类型，直接采用默认类型。
3. 检查数量、ID 分配、名称和目标设备支持情况，在候选副本中创建端口。
4. 需要关联参数时同步创建，例如新增 SWITCH Case 时创建条件行。
5. 一次提交端口和关联参数；自动重算尺寸与连线锚点，新口显示为“未连接”。

子过程新增外部数据接口时，子画布同步出现对应的边界接口。用户在子画布连接内部器件，父画布连接外部来源或目标。新增的必选输入在未连接时显示错误标记，可以保存草稿。

### 5.4 删除端口

1. 取得端口、全部连线、子过程边界映射、分支参数及消息/表达式引用。
2. 固定口、default、自动回边等受保护端口直接说明不可删除的原因。
3. 已连接或被参数引用时，列出影响：“将删除 3 条连线；日志消息第 2 项引用该输出”。用户可取消；默认不进行删除。
4. 用户确认后，在一个事务中删除端口、关联边、子过程映射和所属 Case。其他器件中仍需用户选择替代来源的引用转换为显式未绑定项：`BindingState=unbound`，保留原器件、端口和用途说明供修复，不再作为有效端点参与解析。禁止静默改接到相邻端口。
5. 校验所有有效引用均能解析，且待修复项均已转换为显式未绑定状态，再提交；失败恢复端口、连线和参数。未绑定项可以保存草稿和提交父会话，禁止运行导出；仍指向已删除对象的普通有效引用属于结构损坏，必须回滚。

只断开连线时保留端口和参数。删除端口与断开连线使用不同菜单，确认框说明区别。删除后新增端口使用新 ID，避免旧引用意外指向新口。

### 5.5 调序、类型修改及设备端口索引

上移、下移只改变 `Order`。SWITCH 同时改变判断优先级，预览明确提示“靠前条件先匹配”。default 在画布固定显示于 Case 之前，判断时在全部 Case 未命中后执行。

连接后的端口修改数据类型时，先检查所有连线及引用；不兼容时列出需要删除或改接的内容，确认后统一修改。数据输入源替换同样原子处理旧源的目标记录和新源记录。

导出适配器为每个器件、每个方向建立“工程稳定端口 ID → 实际运行端口 ID”表。目标 `PortAddressing="index"` 可将端口 ID 密排，`id` 模式保留稳定 ID；输入来源、输出目标及日志引用同步使用对应映射。日志 wire 引用必须匹配实际写出的 `Outputs[].Id`，不能另取排序后的数组槽位；禁止假定数组位置天然等于端口 ID。

工程中的 `$器件.端口` 引用按稳定端口 ID 保存和编辑，不按 Order 或输出数组位置解析。运行导出再由映射表生成实际运行端口 ID，见第 7.5 节；不把历史索引文本静默解释为另一端口。

## 6. 子过程与分层编辑

### 6.1 子过程的执行含义

子过程把同一任务中的一段逻辑收在一个图标内。原任务的扫描周期、使能和运行线程保持不变；内部的积分、定时器等状态继续属于各自器件。

普通顺序子过程提供一个控制入口和一个“完成”出口。内部 IF、SWITCH 可以有多条结束路径，这些路径汇到同一个完成出口。父画布从完成口连接后续器件。

只含数据计算、依靠外部消费者决定执行时机的一组器件，也可以组合为子过程。这类子过程只显示所需数据接口，按原有数据依赖调度。组合时不额外生成一条顺序执行链。

循环体中的一段逻辑可以组合；整个循环也可以组合。组合范围切到循环头、回边或分支中间时，要按第 6.3 节检查结构完整性。包含特殊跳转的子过程，在图标上显示独立转移口和去向，详见第 6.4 节。

### 6.2 从多选创建子过程

框选菜单和工具栏增加“组合为子过程”，与旧“任务编组”分开。完整流程如下：

1. 用户在活动画布选中至少两个器件，已有子过程图标可以参与。文字说明可以一同选择；选择的折线不决定成员范围。
2. 校验成员属于同一任务、同一直接画布。其他层的器件通过先返回所属画布再组合。
3. 分析全部相关连接，分为内部连接、外部进入、向外输出、正常后继和特殊转移。
4. 打开预览，填写名称、子过程编号；列出成员数、数据接口和控制接口。接口可改名，默认保留来源器件和端口名称作为提示。
5. 校验单入口、分支和循环边界；失败时列出具体原因，并提供“补选完整结构”或取消。
6. 创建子画布，把成员和内部连接移入其中，身份保持不变；父画布用一个 `SUBPROCESS` 图标替换所选内容。外部线改接图标接口。
7. 一次提交完成组合，选中新图标。整个操作记录一条编辑历史；取消预览保持原图不变。

子画布使用局部坐标。首次组合时，以所选内容包围框左上角为基准减去偏移，再加一圈编辑留白，保留成员相对位置。父图标放在原选择区附近。以后移动父图标不改变内部坐标。

### 6.3 可组合范围和结构检查

组合前先把选择范围投射到执行关系中：

- 普通顺序区允许多个外部前驱汇入同一个内部入口；这些来路共享图标控制入口。
- 所有普通完成路径的外部后继必须一致，或全部结束当前段。后继不同的普通路径先补充清晰的外层选择结构。
- 外部控制边不能直接进入第二个内部节点、循环体中段或 SWITCH 某个 Case 中段。
- 选中完整 IF、SWITCH 或循环时，应包含其结构头、内部成员、回边及必需出口；选中某个分支中的连续片段时，该片段保持原分支归属。
- 控制汇合允许多条来路；数据输入继续一口一源。
- 输出数据必须在所有使用它的正常路径上有效。来自未执行分支的旧值不能自动作为本次返回值。
- 未接线、参数未填等一般编辑问题可以作为草稿保存；跨任务引用、重复所有权和层级环等结构损坏不允许提交到父图。

新增结构归属记录，明确器件处于哪个 IF 分支、SWITCH 分支或循环体。归属按稳定 ID 和分支 Key 保存；移动图形位置不改变执行归属。

### 6.4 子过程边界与父子连线

**数据输入：**默认每个被外部连接的内部输入生成一个图标输入口，即使它们暂时来自同一个外部源也分别保留。用户可以在子画布中让同一边界输入连接多个内部消费者，这与数据输出扇出使用相同的类型规则。

**数据输出：**每个向外供值的内部输出生成一个图标输出口；其多个外部消费者共用该输出。内部同时使用该值时，内部连线照常保留。一个数据边界输出只有一个内部来源。

**控制入口和正常完成：**父图连接图标的入口、完成口；子画布显示“进入本子过程”“完成并回到父流程”的边界接口。入口指向内部唯一入口，多个正常尾可以汇入完成接口。

**特殊转移：**已有 JUMP 回循环头、提前退出循环或结束本轮任务等路径单独保存，图标显示“继续 W1”“退出 W1”“结束本轮”等接口。转移接口记录目标种类、所属结构及目标，不与正常完成混合。

工程层的特殊转移以结构化 `TransferTarget={TargetKind, StructureId, TargetElementId}` 为权威目标。用户通过目标选择器编辑该记录，控制连接引用对应转移接口；JUMP、WHILE、SWITCH 参数中的运行编号由编译器生成，不在工程中另行维护一份可编辑目标。结构的实际头、出口由任务级结构记录解析，不能通过显示名称猜测。

孙层转移到外层循环时，沿所属画布的祖先链逐层建立接口桥接，每级接口引用直属父层的稳定接口身份，最外层声明保存权威 TransferTarget。打开、保存及编译时逐级核对，最终解析到被授权结构的头或出口；任一接口缺失、目标已删或目标不再是祖先结构时，保留诊断并阻止运行导出。修改外层结构先计算全部桥接影响，再同事务更新；解散一层时折叠该层桥接，保留剩余接口和实际目标。

1. 整个循环封装到子过程后，回跳留在内部。
2. 仅封装循环体片段时，指向外层循环头或出口的跳转经过明确转移接口；预览显示原目标，保存时再次校验仍属于原来的循环结构。
3. 子画布内新增指向外层的跳转，只能从可用的外层结构接口中选择。普通节点列表只列当前层目标。
4. 转移到兄弟子过程内部、另一分支中段、未声明外层目标时拒绝编译。
5. 原文件中 `NextID=-1` 的明确“结束任务本轮”语义保持；组合预览若发现该路径，显示独立终止接口。普通未连线尾端保存为“未配置”或“正常完成”，由用户明确选择。

`-1` 只在最后生成运行配置时表示任务终止。工程层使用 `TargetKind=element|subprocessReturn|loopContinue|loopExit|taskEnd|unbound` 区分去向。

每条父子连线都能追踪到图标接口和内部实际端口。父图只画到图标，子图只画到边界接口。边界接口可显示父侧来源或使用者的只读摘要，并提供“返回父画布定位”。

### 6.5 在上层打开子画布

右侧编辑区域增加 `CanvasWorkspaceHost`。双击子过程或点击“编辑子过程”时，在父画布上方显示子画布编辑层：

- 顶部显示“任务 → P001 名称 → P004 名称”的路径导航。
- 提供“保存子过程”“保存并返回”“返回”“关闭”及未保存状态。
- 父画布保持原视口，在遮罩下停止鼠标、键盘和拖放命中。
- 左侧器件栏一直可用，所有操作进入最上层活动画布。
- 子画布内可继续创建和打开子过程，形成根、子、孙多层。
- 每层独立保存选择、视口、倍率、连线预览和编辑历史。

不使用阻断整个主窗口的模态弹窗承载子画布。属性窗口可以继续按现有模式弹出。

工具栏的“清空”改为“清空当前画布”，确认框列出当前层名称。整个工程的清空保留为单独命令。任务参数显示所属任务，子画布内修改任务周期会影响同一任务的全部层级，确认框应明确这一范围。

### 6.6 左侧添加和交互目标

所有命令先取得 `ActiveCanvasContext`，然后执行：

```text
器件栏单击 → 当前视口中心 → 当前任务、当前画布
器件栏拖放 → 活动画布局部坐标 → 当前任务、当前画布
文本添加、复制放置、删除、连线 → 当前画布
工程保存、运行导出 → 文档级操作，先处理打开的子会话
```

拖放开始时记录源操作，只有有效 Drop 或明确的单击命令才新增器件；取消拖放不触发“默认中心添加”。层级切换前取消临时连线和复制预览，结束移动或尺寸调整，释放鼠标捕获，避免旧层的 MouseUp 落到新层。

编辑状态统一为：空闲、框选、移动、调尺寸、连线、复制预览、属性编辑、提交中。一次只允许一种交互。子画布关闭时解除事件订阅、计时器和图形引用。

### 6.7 工作副本、保存和取消

进入子过程时创建 `SubprocessEditSession`，包含子树工作副本、进入基线及父图关联信息。父图暂不修改。对子接口的删改在会话中记录待应用差异，直到保存时再与父线统一提交。

会话同时保存任务级候选差异，覆盖任务周期、日志设置、结构归属和积分存储配对。子画布中的修改先进入本层候选，孙层保存合入子层候选；本层放弃时一并丢弃。本层保存把子树、接口、父连接和这些任务级差异一起校验、一次提交，涉及任务周期时重新校验全部受影响层的间隔参数。不会直接修改共享任务对象。

| 操作 | 行为 |
| --- | --- |
| 保存子过程 | 校验当前工作副本，将子树和接口差异一次合入直属父工作图；留在当前层，更新本层基线 |
| 保存并返回 | 执行同样提交，成功后关闭本层，恢复父视口并选中图标 |
| 关闭或返回，有未提交修改 | 提示“保存并返回 / 放弃本层未提交修改 / 继续编辑” |
| 关闭或返回，没有未提交修改 | 直接返回父层 |
| 孙层提交给子层，子层尚未保存又放弃 | 孙层的修改随子层工作副本一起放弃 |
| 本层已执行过“保存子过程”后继续编辑再放弃 | 只放弃最近一次保存之后的未提交修改，父图保留已提交版本 |
| 根文件保存时有打开的子层 | 在独立候选会话栈中逐层合并到候选根图；任意取消或结构校验失败则停止，不先关闭真实会话 |
| 退出程序、换文件、重新加载、导航离开 | 统一检查会话栈及根工程；文件保存失败或另存为取消时保持当前界面 |

界面明确区分“已提交到父画布”和“已保存到工程文件”。子过程保存不自动写磁盘；根工程保存成功后才显示文件已保存。

允许缺少必填参数或未接线的子图作为草稿提交，图标汇总错误数量，工程保持草稿状态。引用损坏、非法边界或重复身份等错误要修复后才能提交。

根保存的候选会话栈、根图和编译结果先在独立快照中完成；磁盘提交前不切换真实会话栈、活动层、局部及工程基线。提交前失败时原文件与正式编辑状态不变；提交后清理失败仅告警，不回滚已提交文件。【实现缺口】当前 EditorWorkspaceViewModel.Save 先 Resolve 再 SaveProject（:836-838），尚不能据此宣称完整会话回滚已满足。

### 6.8 接口编辑、删除与解散

- 子画布左、右侧增加“边界接口”区域，可新增、改名、排序和删除数据接口；控制入口、完成与特殊转移按执行结构管理。
- 删除已在父图使用的接口，先列出受影响父级连线；用户确认后将删线加入待提交差异。用户取消会话，父级连线保留。
- 删除内部数据输出来源时，必须同事务删除或改接对应输出接口。删除一个内部消费者，只移除其映射，其他消费者保留。
- “删除子过程”确认后删除整个子树、图标及父级相关连线。
- “解散子过程”把内部节点恢复到父画布，拼接边界前后的实际连线，保留器件身份和内部相对位置。嵌套子过程图标作为完整成员移动。
- 解散位置以当前图标位置为基准计算，避免回到创建时的旧坐标；手工路径点按相同平移转换，接口桥接的局部路径可重算。
- 空子过程可以保存草稿；若只有明确控制入口、完成口，运行展开为直通。数据输出没有来源时禁止运行导出。

### 6.9 复制子过程

扩展现有复制预览，支持完整子树。提交前一次生成映射：

1. 为图标、普通内部器件、嵌套图标、画布、连接和结构分配新身份及目标任务内子过程编号。
2. 普通端口 ID 在新器件内部保持；重写全部内部端点、边界、控制归属及跨层转移。
3. 重写 IF 参数、SWITCH 分支、WHILE 继续/退出、JUMP 目标、日志消息来源和积分/存储配对。
4. 内部连线保留；复制范围外的输入、输出和转移断开，列出待重连项。
5. 自动存储名生成新身份，实时库点位是否另选由用户确认；同点位重复写入累计或恢复值时禁止不经确认直接导出。
6. 复制不携带设备累计值、存档标记、边沿基线、循环计数和日志文件。

复制预览在活动画布提交。跨任务复制采用目标任务周期，重新检查积分及打印间隔。未提交预览不修改工程正式编号；取消后原图不变。

### 7.2 SWITCH：动态分支

**端口和操作：**设备侧只有一个数值选择输入（端口名 `Command`），**无数据输出口**，命中分支通过 `nextId` 跳转。工程侧仍按编辑需要画出逻辑控制入口，以及输出区第一行的固定 default 和其后的 0～8 个 Case 出口。新建默认一个 Case 和一个 default；可以删掉全部 Case，保留默认分流。运行不导出这些编辑出口，只下发 `SwitchPara`。

属性页每个 Case 展示稳定编号、算子、Value、必要时的 Value2、条件摘要、目标。提供增加、删除、上移、下移。目标选择器与画布连线编辑同一份连接，修改一处后另一处同步。子画布中只选当前层目标或已声明的边界出口。

| 算子 | 匹配规则 |
| --- | --- |
| EQ（缺省） | `abs(x-Value) <= 0.000001`，容差固定不可配置 |
| GT / GE | `x > Value` / `x >= Value` |
| LT / LE | `x < Value` / `x <= Value` |
| RANGE | `Value <= x < Value2`，要求 Value 小于 Value2 |

`Op` 字符串区分大小写，省略时按 `EQ` 处理。`Value` 必填，整数或浮点均可；本方案选择新 Case 明确默认 `Op=EQ、Value=0`，界面标明这是上位机默认，不宣称已有“待填写”状态。`Value2` 仅 RANGE 必填且须大于 Value，其余算子不导出或写 0。数值要求有限，按不依赖地区的格式保存。

选择器执行时读取一次，按 `Cases` 的 Order 先命中先走；条件重叠或相同均允许，界面给出优先级警告，不能把宽泛条件放在前面还宣称顺序正确。

工程保存每个分支的条件、稳定 Key、PortId、顺序和绑定状态，并区分三种去向：

1. 已连接普通目标：导出实际运行编号。
2. 显式选择“结束本轮”：导出 `-1`，该分支匹配后结束本轮。
3. 未配置（unbound）：仅 Case 按第 3.4 节逐项确认后从本次运行副本剔除；不确认或取消不生成／替换运行文件，再次导出须重新确认。条件、CaseKey、PortId、Order 和草稿诊断不变。剔除后继续匹配后续 Case／default，不等于命中后结束。

运行参数使用 `Params[0].Name="SwitchPara"`：`DefaultNextID`、有序 `Cases[{Op,Value,Value2,NextID}]`；顶层 NextID=-1，不导出 Epsilon。default 不可删除，须绑定当前层合法目标、声明的正常完成接口或显式结束本轮。未绑定 default 可存 draft、禁止导出，不能省略 DefaultNextID 自动修复。协议缺省 -1 仅为设备解析规则；显式结束才输出 -1。正常完成绑定父级后继，与任务结束分开。导出须校验目标存在，不以设备遇到失效目标后结束并打日志代替校验。

例：`RANGE[100,200) → A`、`GE200 → B`、`EQ5 → C`，其他到 D。输入 100 到 A，200 到 B，5 到 C，50 到 D。删除第二项后，第一项、第三项和 default 的连接保持原身份。

### 7.3 WHILE 和 JUMP：实时条件与回跳

#### WHILE：两种退出模式

WHILE 无数据端口（`inputCount = 0`、`outputCount = 0`），不从连线取数。工程侧保留 1 入 2 出的流程语义：入口只表达执行顺序，两个出口分别为“继续”（跳循环体首）和“退出”（跳循环出口）。属性提供 `Link`、`Dev`、`Reg` 选择器、继续与退出目标、退出模式和最大迭代次数。

参数对象名为 `linkdev`，取值如下：

| 字段 | 本次编辑及校验 |
| --- | --- |
| Link / Dev / Reg | 条件遥信点位；`Link` 在合法链路范围内，`Dev`、`Reg` 非负。两种模式都必填 |
| ContinueNextID | 继续分支目标，`0 ~ 499`；必须有效 |
| ExitNextID | 退出分支目标，`-1 ~ 499`；`-1` 表示退出即结束本轮 |
| LoopMode | `1` 最大迭代（缺省）、`0` 条件遥信；其他值解析失败 |
| MaxIterations | 计次模式迭代次数，`1 ~ 100000`，缺省 `200`；条件模式不使用，仍按缺省值写出 |

两种模式的执行语义：

- **`LoopMode=1` 最大迭代（缺省）：** 进入循环后执行 `MaxIterations` 次即自动走退出分支，**不读遥信**。此时遥信点位仍参与解析校验，但不影响分支选择；界面必须明确提示这一点，避免用户以为接线了遥信就会按遥信退出。
- **`LoopMode=0` 条件遥信：** 每次到达重新读取遥信，`=1` 走继续、`=0` 走退出。非零按真处理；`GetYxValue` 接口未注册时按假处理并走退出分支，**不设迭代上限**。

计次模式的计数复位规则：从上游进入（到达时上游元件标识等于 `Inputs[0].SourceElemId`）时计数清零；循环体末 JUMP 回跳时计数继续累加；计数达到 `MaxIterations` 时清零并走 `ExitNextID`。`Inputs` 缺失时不做上游识别，计数只在完成退出时清零。

运行 WHILE 静态 NextID=-1。协议可缺省 Inputs，但依赖“重新进入即复位”的计次循环不能省略入口识别：先完成子过程展开、数据调度和辅助节点，再确定最终普通入口直接前驱；多普通前驱汇入专用入口 JUMP，SourceElemId 使用该运行 ID。回边、continue、体末回跳不得经过此复位入口。该字段是控制元数据，不要求前驱数值输出口，不生成 `$elem.port` 数据引用。目标协议无法表达或保证时禁止相关导出。0～499 只约束最终运行目标，工程 ID 可超过 499；ExitNextID=-1 单独表示任务终止。LoopMode 和 MaxIterations 两种模式均显式写出，不依赖设备缺省。

提前 break、外层 continue 或跨层退出本身不清零；只有下一次完整进入必经专用识别入口才能复位。嵌套／跨层转移无法保证这一点时禁止导出，或先取得设备重置契约。do-while 首次 Body、回跳与 MaxIterations 的精确次数关系待设备轨迹确认。

【实现差距】WhileDesignInfo 的 MaxIterations=1000 和 LegacyResetIntervalMs=20 目前为只读 JsonIgnore，尚无 LoopMode；WhileRuntimePara 与 RuntimeGraphBuilder 仍输出旧五字段，RuntimeConfigAdapter 还无条件删除新 WHILE 的 Inputs。旧五字段交给新设备可能被缺省解释为计次 200，不能视为原 UI 条件循环等价。迁移必须让用户确认模式，配套 DTO、属性、转换、契约版本和能力门控一起完成。

#### JUMP：静态跳转

JUMP 在工程中有逻辑入口、只读目标引线和属性目标选择器；运行只写静态 `NextID`，无 `Params`、无 `Inputs`、无端口，`Execute` 不修改 `nextId`，由加载器统一解析目标。工程目标必须是同任务存在的合法节点或声明的转移接口；`-1` 表示结束本轮，其余目标编译后须落在 0～499。目标不存在时设备结束本轮并打日志，上位机导出前必须校验目标存在。回边渲染为带“下一轮”标识的线或短目标标记，不靠目标编号大小猜方向。

#### 结构记录与循环安全

编辑服务建立 `LoopStructureInfo`：结构 ID、WHILE 头、Body 入口、退出目标、成员、父结构及分支、授权回边、`LoopMode` 与 `MaxIterations`。源文件中无歧义的回跳可迁入；交叉回跳、外部跳进体中间等情况保留诊断并阻止运行导出。

旧方案通过 20ms 间隔判断新进入、固定 1000 次上限防护；该时间窗在慢迭代中会重复清零，在快速再次进入时又可能残留计数。器件文档已改为“上游进入识别 + 可配置 `MaxIterations`”，本文采用新规则，不再沿用 20ms 时间窗。但条件遥信模式**没有迭代上限**，遥信恒为 1 时属于设计行为内的持续循环。因此发布条件要求设备另有按扫描开始重置的全任务步数、时间预算及停止检查；该能力未经确认前，条件模式的循环禁止运行导出。上位机展示保护参数与模式风险，不凭“画了循环”宣称运行必然安全，也不把 `MaxIterations` 当作条件模式下的保护。

用 IF 选择 JUMP 到循环出口表示提前退出，到 WHILE 表示继续判断；子过程封装时使用第 6.4 节的转移接口。先执行体再回 WHILE 的组图可以表达先执行后判断，编辑器显示实际入口，避免把进入点改成 WHILE 导致少执行首轮。JUMP 只放在“必然要跳”的位置（循环体末）或已被 IF 筛选过的分支之后，放在循环体链中间会截断流程，编辑器给出警告。

### 7.4 ALGO_INTEGRAL：积分与配套存储

固定输入 0“被积函数值”，固定输出 0“累计量”，均为遥测数值。名称不决定物理单位，属性提供输入、累计量单位说明；输入为功率 kW 时，需要上游换算为 kWh/s，内部统一用秒计算累计量。

运行参数必须满足 `Params[0].Name="IntegralPara"`（源说明第 29 行）；工程内部按名查找不能代替这一运行位置契约。参数字段如下：

| 字段 | 本次编辑及校验 |
| --- | --- |
| Interval | 非负整数；0 表示每次到达可处理，但首轮及基线重建时不积分；正值是最小门限，不是步长，允许等于或小于任务扫描周期，并提示不会提高实际采样频率 |
| IntervalUnit | 工程保存 ms 或 s；运行枚举 `0`=ms、`1`=s，其他值设备解析失败，属性页不提供其他选项 |
| LinkNo / DevNo / RegNo | 定位累计量所在实时库点位，必须选择有效、可写、单位匹配的数值点；点位类型只接受 `Type_YC`、`Type_DD`，`Xishu` 必须有限且严格等于 1.0 |
| IsPersistent | 是否配置配套 SAVE_DATA；新建时询问，未选择前不自动写 true。设备侧代码不解析该字段，仅组态使用 |

顶层 `Inputs` 必须恰好 1 个且来源有效；不满足为运行就绪错误，可保存诊断草稿，禁止 ready／运行导出，不能下发后才等待设备解析失败。

源资料未给默认值的字段在本次明确：Interval 初值 0、单位 ms、点位未选、IsPersistent 初值 false。用户确认新建时选择持久化，再创建配套；未选点位的器件可以保存草稿，但禁止运行导出。

**源说明明示的积分规则：**使用 CLOCK_MONOTONIC 实测时间；首次读取库基值并建立时间基准，不积分；之后按 `累计 += 本次输入 × 实际经过时间（秒）` 做矩形积分。门限未达不更新积分计时基线 lastTickMs，实际时间可跨周期；double 累计、float 写库和输出。“计时基线”不预先承诺写库失败时的提交顺序。

源说明明示的边界与待确认异常分开：

- 【待联调】分别注入无效输入、时钟失败、读库失败、写库失败，确认增量提交、内存累计、库值／输出一致性、基线、返回值与诊断通道；未确认前不宣传“不伪造增量”“自动断基线”“不跨异常区间补积分”或“必然报告缺口”。
- 【源契约】超过 10 分钟未执行时放弃该段并重建时间基准；是否报告缺口未定义。阈值前、恰好 10 分钟、超过阈值分别采证；内部比较与实际计时基准（相邻到达时刻还是 lastTickMs 等）须经设备源码或联调确认，不预设恰好阈值按 `>=` 丢弃。
- 运行期间实时库值被其他器件改写：检测到与上次写入值不一致时，以实时库当前值重新同步累计基值。
- `Reset` 只重建时间基准，不清除累计值与实时库值；界面不得把它宣传为“清零累计”。

外部改写后同次是否继续积分、是否重建时间基线及浮点比较容差尚未定义，列为联调；上述异常策略未确认前不得作为设备保证。修改单位显示、尺寸或名称不清库；改变点位／物理量须确认累计周期。

**持久化自动配套：**同目录存储方案明确输入仅透传，存档值独立读取实时库。本次使用这一链路：

```text
上游被积函数 f(t)
       ↓
SAVE_DATA：透传 f(t)，首次先恢复累计实时库 C，之后按策略保存 C
       ↓
ALGO_INTEGRAL：读取 C0，以 f(t) 和实际 dt 更新同一点位 C，输出累计量
```

该连接安排 SAVE_DATA 先于积分到达，并保留被积函数数值；只有设备恢复失败确实阻断后继时，才能保证积分首次读取恢复后的值。源说明的返回 -1 不单独证明阻断已实现，须联调。存储保存本次积分前的库值，归档延迟还受到达、保存策略及失败影响。

自动创建的设计目标是同事务完成器件、同点位、配对和上游→存储→积分连线。当前 EditorElementWindow 自动配套仅创建存储和配对，尚未闭合完整链路；RuntimeConfigAdapter 的同点位存在检查也不证明绑定或执行顺序。IntegralStorageBinding 保存双方 ID，复制重映射，存档名与显示名分开。

保存保留就绪诊断；运行导出须检查指定配对、同任务同点位、真实上游→SAVE_DATA→积分链路，所有可达积分的路径都先经过配套存储。展开、复制、分支绕行后重查；未接输入只能存草稿。删除配对提示关闭持久化或重建，关闭不擅自删除用户器件。

### 7.5 DEBUG_PRINT：源选择、触发和消息引用

**端口：**`IN0` 为上游器件输出，既是日志来源也是透传值，必须连接；`IN0` 断线或上游未执行时器件返回 -1、本轮结束。`IN1` 为触发量，可不接线，接线后用于边沿判断；`OUT0` 每周期输出 `IN0` 的值，透传语义唯一。运行 `Inputs` 数量为 1 或 2，`Inputs[1]` 缺失或字段不全表示悬空、不启用边沿。之前设想的 `IsInputTriggerValid` 字段在器件文档中不存在，本次不新增该字段，改由 `IN1` 是否接线决定边沿是否参与判断。

**开关层级：**链路总开关 `MasterPrintEnable` 写在配置文件根级（缺省 true），其下为器件开关 `EnablePrint`（缺省 true），再下为“边沿 ∨ 周期”。任一关闭时器件退化为纯透传：不取日志、不拼消息、不写文件；屏幕打印不受影响（`KSH_DEBUG` 打开时 `KSH_DEBUG_PRINT` 仍先打印到屏幕），因此界面不得把开关关闭描述为“关闭日志”。热加载时链路总开关以配置文件为准，覆盖运行时设置。

【拟实现】MasterPrintEnable 是目标运行配置／日志链路的单一权威根级值，不按任务分别输出；工程保存该值以便恢复，TaskLogSettings 不是其同义替代。当前 LogicEngineConfig 无此字段、DebugPrintBasicPara 无 EnablePrint；字段及消息转换未确认时阻止相关目标导出，不通过省略字段依赖设备缺省 true。关闭时工程与运行配置保留合法模板和引用，重新开启无需重配；只有未配置或用户明确移除才省略 CustomizedMessage。

参数对象保留 `Debug_Print_BasicPara`：

| 字段 | 行为与本次默认 |
| --- | --- |
| EnablePrint | bool，器件开关，缺省 true；新建默认 true |
| PrintEdge | 运行必填；0 上升、1 下降、2 双边沿；上位机新建默认 0，运行显式写出；编辑草稿另保留 Disabled=3（未确认运行协议，不生成运行配置） |
| PrintfCycleMode | 必填；0 每次到达，1 到周期才打印；上位机新建默认 0，运行显式写出 |
| PrintfCycleInterval | 周期模式必填，正整数 ms，必须 > 0 且不小于任务扫描周期；每次模式忽略该值，初值取当前任务扫描周期 |
| IsPrint_Timestamp | 缺省 true；取源产生、消费、消息生成或刷盘时刻待设备确认 |
| IsPrint_LinkNo / IsPrint_ElementId / IsPrint_ElementName / IsPrint_PortId | 缺省均为 true；显示 `IN0` 所选择日志源的信息。关闭的段连同方括号整体省略；器件名取**类型名**，实例名不入库；`[ID自身ID]` 段固定打印 |
| CustomizedMessage | 可选，缺省时只做日志放行；含 `Message_Format` 与 `Message_Valist` |
| CustomizedMessage.Message_Format | 仅允许准确 `%f`，也可为纯文本；拒绝宽度、精度（如 `%.2f`）、`%%`、其他转换和孤立 `%`；上限 128 UTF-8 字节 |
| CustomizedMessage.Message_Valist | 个数必须等于 `%f` 个数，最多 8 个 |

**Disabled 编辑边界：**提交 `411b45a` 明确新增 `Disabled=3` 及“关闭边沿触发”选项；现有设备设计仅确认 `0/1/2`，不能据此猜测 `3` 的生产行为。属性应用、任务周期编辑允许保留 `3`，工程保存为 `draft` 并恢复完整 `CustomizedMessage`；运行编译及严格导出仍拒绝 `3`，不覆盖导出目标，不自动改为 `0`、断开 IN1 或关闭器件。周期模式 `0` 的新 UI 文案“不使能周期打印”也不构成新固件语义证据，本次不改变既有运行解释。

**统一“或”闸门：**两开关开启后，周期与边沿任一满足即开本次闸门，同时决定所读源日志是否入待写缓存、自定义消息是否生成。模式 0 周期恒满足，首次即可开闸；模式 1 首次只建周期基线，之后按间隔判断。IN1 悬空不参与，接线时首次建边沿基线，之后 0→非0 为上升、非0→0 为下降，两者为双沿。边沿打印刷新周期计时。闸门关闭时可读日志取出即丢、游标推进，不跨后续周期或边沿补打。非法触发值／NaN／Inf 的处置及是否清基线未定义，列待联调；有效 IN0 继续透传。

属性界面提供格式文本、可增减实参列表及预览。每个参数可选择“器件输出”或“实时库点位”：

- 工程中保存结构化引用：器件 ID、稳定输出口 ID，或经过校验的实时库身份。
- 编辑文本仅接受 `$元件ID.稳定输出端口ID` 和 `#实时库号`，例如 `$41.91`、`#62`；编号须为非负 Int32。括号仅用于解释，不属于输入；拒绝 `#(链路,设备,寄存器)`、常量和表达式。
- 导出时通过 `OutputPortMap` 生成 `$26.3` 等引用，其中 3 必须是对应运行元件实际写出的 `Outputs[].Id`，不是数组槽位。id 模式下，源 41 的稳定输出 91 即使位于数组首项，仍导出 `$41.91`；index 模式可以改变实际输出 ID，但引用须同步匹配。工程端口重排不能改变绑定对象。
- `#62` 通过实时库目录唯一解析；未知或歧义目录不能伪造库号。未解析的既有绑定保留证据并显示诊断，不能绕过应用校验。
- 格式解析仅识别准确 `%f`，校验占位数量等于实参数量；预览使用固定六位小数。`%%` 也拒绝，不作为百分号转义；非法格式不能应用或运行导出。禁止直接将任意用户文本作为设备 printf 的格式串。
- 超过 128 字节、实参超过 8 个、非有限值和失效来源给出具体位置诊断。`$a.b` 引用的器件不存在、`#n` 实时库号越界、周期小于任务扫描周期会导致设备任务启动失败，上位机必须在导出前拦截。

来源连接白名单只决定可采集来源，不替代上述运行闸门。各 DEBUG_PRINT 实例独立维护源日志游标；多个启用且开闸的实例可能分别记录同一源日志，源说明未保证全局去重。按源身份去重范围、实例头部保留与任务级采集去重均待联调，不作验收前提。

【跨层引用采用规则】日志实参按展开后同任务稳定器件身份解析，不强制生成普通数据边界；这是拟实现方案，当前 ElementReferenceService.ValidateForExport 仅支持同 Canvas，须调整后才能开放。组合／解散保留来源身份，复制范围内来源重映射、范围外转 unbound；来源删除转 unbound，互斥分支或无法证明本次先产生再消费的来源拒绝导出。仅日志参数跨边界、无普通连线也纳入事务分析及验收，不能假定普通边界服务自动处理了隐藏引用。

**日志文件与缓冲：**源契约规定待写缓存非空且到达 10 秒条件时批量写文件，不等于后台 I/O 保证。实际打开／写入／关闭线程、最大阻塞时间、刷盘与扫描抖动待联调；只有确认设备钩子后才可使用“后台消费者”条件设计。

- 路径：`/data/app/e9361app/record/c{链路号:02d}{规约号:02d}/DebugPrint.log`，同一链路的所有打印器件共用该文件，文件句柄与写入序号按链路共享。仅在已确认的序号可表示范围、有效文件及正常重启／热重载条件下验证 `S+1` 续写；不保证任意重启后序号必然连续。
- 格式：按源说明暂采用 1024 槽、每槽 1040 字节（声明的槽头 16 字节加正文 1024 字节），总计 1,064,960 字节，即 1.015625 MiB。槽头格式 `[S%06u,L%04u]\n` 的实际编码、填充及序号可表示范围须联调核对；在上述有效范围内写槽 `(S-1)%1024`，满后覆盖最旧，打开时取有效槽最大 S+1，文件不存在或大小不符时重建。序号超宽／整数回绕、掉电半写及损坏槽头的识别与恢复分别验收，不套用正常续写结论。
- 缓冲：任务级缓冲 8 槽，满了覆盖最旧记录并累加 `logDropped`，不阻塞；器件待写缓存 64 条，满了丢弃新记录并累加 `pendDropped`。
- 失败与掉电：源契约为打开失败保留缓存、写入失败丢弃本次剩余记录。10 秒是批处理触发条件，不是严格掉电损失上限；实际损失受到达间隔、闸门、溢出、文件故障、操作系统缓存及介质持久化影响。槽原子性、半写识别和重启恢复须联调，不保证已刷盘槽必完整。按第 7.1 节共享句柄暂定规则销毁实例，最终关闭机制须确认。
- 超长记录按 UTF-8 边界截断；框架级日志（任务启动/结束、元件执行失败等）不属于任何器件，只上屏幕、不落盘。

上位机只负责参数编辑与容量提示，不实现写文件策略。旧资料中的 RAM/Flash 双 1MiB 文件轮转、`log.1` 后接 `log.0`、`/tmp` tmpfs 挂载和每任务 64KiB 队列未被器件文档采纳，本次不作为实现依据，改列第 12.2 节待确认项；与之相关的下载、传输功能同样不在本次契约内。

### 7.6 SAVE_DATA：单点持久化和透传

固定 1 入 1 出，输入仅透传，不决定被保存的实时库点位。缺少 Inputs 时设备可能使用默认索引 0，透传结果不可依赖，不能保证输出 0。未接输入允许带诊断保存 draft；ready／运行导出必须唯一有效输入。当前 ElementSaveData.HelpInfo 的“未连接输出0”和 IsRequired=false、NewElementsTests 的可选输入断言属于实现差距，不是设备行为证据，本轮不修改该代码或运行测试。

参数对象名为 `SaveDataInf`，字段大小写按源方案保留：

| 字段 | 编辑及校验 |
| --- | --- |
| name | 自动生成、只读、同文件唯一，最多 63 个 UTF-8 字节；独立于 Name。为空时设备解析失败、任务不启动 |
| link / Dev / Reg | 保存及恢复的实时库点位；`link` 越界、`Dev`/`Reg` 为负或实时库号换算失败 → 解析失败，任务不启动 |
| SaveByTimeEnable / SaveTime | 0/1；设备缺省 0（关闭），上位机新建默认 1 并默认 60 秒，必须显式写出，不能依赖设备缺省。启用时周期为正整数秒 |
| SaveByChangeEnable / ChangeDeadZone | 0/1；设备缺省 0（关闭），上位机新建默认 1，默认死区 1；非负有限数 |
| InitValEnable / InitVal | 设备缺省 0、0；当前上位机新建默认 1、0。初始偏移须有限且在 float 范围；虽设备兼容布尔使能，运行统一输出整数 0/1 |

按周期和按变化量可以同时开启。【拟定／待设备确认】任一条件满足时存档一次，普通变化量使用严格大于死区的比较；源说明未展开这些细节，同时命中时的合并、保存成功／失败后的计时与变化基线更新均须经设备源码或联调确认，不作为已证实的设备行为。YX 按源方案使用固定 0.1 阈值且不受 `ChangeDeadZone` 影响，并提示不建议配置初始偏移（写库按 0/1 截断）。

周期与变化两种后续存档策略都关闭时，仍保留每次进程启动后的首次恢复／建档，以及满足条件的一次性初始偏移、数值与标记写入；首次恢复失败仍按规定重试。关闭这两个开关不等于禁用器件或完全不写文件，界面应明确提示并由用户确认。首次恢复写实时库失败时器件返回 -1、`FirstDoFlag` 不置位，下个周期重试，组态不得把该状态解释为存档已成功。

三个使能字段 SaveByTimeEnable、SaveByChangeEnable、InitValEnable 均显式写整数 0/1。设备省略字段按 0；上位机新建显式 1/1/1，两者不行为等价。导入须按字段是否存在区分设备缺省与新建默认，不能直接用 DTO 初始值推断；显式 0 保存、回读和再导出仍为 0。

存档目录来自运行功能链路号及协议号，例如 `c0357`，与点位参数中的 link 分开。实际文件为 `record/cXXXX/SaveData.json`，以 name 和 `name_InitDone` 保存值与初始值标记。自动名称同时避开其他名称及其 `_InitDone` 辅助键；复制生成新 name，改显示名称保留原 name。

首次运行优先恢复历史值，无历史取实时库当前值；启用初始值且标记不存在时叠加一次。方案采用标记先写、数值后写，掉电窗口可能丢一次偏移，属性说明应如实提示。不能把该标记当作完整数值提交已经成功的证明。

标记写失败时本次不叠加，按源契约下次进程启动重试；这与首次恢复写库失败“下执行周期重试、不置 FirstDoFlag”不同，不可合并。InitValEnable=0 或 InitVal=0 时完全不读写初始值标记。

点位类型、工程值与系数换算按源方案校验，本机 PARA 不支持恢复。改变点位但保留存档名会让旧值影响新点位，因此点位修改必须显示历史继承提示；安全默认生成新存档身份，原设备文件不自动删除。运行文件并发写入、JSON 完整性和系数为零的处理由设备端验证。

### 7.7 新类型注册与契约数据

复用已有 ElementControlFlowSwitch、ElementControlFlowWhile、ElementIntegral、ElementDebugPrint、ElementSaveData、ElementJump、ElementSubprocess 及反射工厂；此次重点是新版契约对齐，不重复创建类型。

沿用 ElementTypesEnum 中已有新 Type，保持既有枚举值。SUBPROCESS 只用于编辑，运行移除图标与边界。SAVE_DATA 源示例数字分类不能覆盖当前枚举，按 Type 契约适配。

参数分别建立只保存数据的类型化对象，代码中简称 DTO。工程内部按名称查找参数，避免工程集合的位置依赖；运行适配器则按各器件源契约固定参数位置，ALGO_INTEGRAL 必须输出 `Params[0].Name="IntegralPara"`，不得因工程集合顺序改变而移到其他位置。每种参数类型配套提供校验、器件引用枚举、引用重映射、历史字段迁移及运行转换。`ContractVersion` 表示该器件采用的字段和执行规则版本；新旧 SWITCH、WHILE 的语义差异通过版本和明确迁移处理，不能仅因 Type 相同就改用新解释。

DTO 字段以第 7.2～7.6 节的参数表为准，本次相比旧方案变化较大的部分集中在这里：`SwitchPara` 的 `Op` 缺省 EQ 与 `Value2` 规则；`linkdev` 增加 `LoopMode` 与 `MaxIterations`；`Debug_Print_BasicPara` 增加 `EnablePrint`、去掉 `IsInputTriggerValid`、五个 `IsPrint_*` 缺省改为 true；`SaveDataInf` 全部使能字段显式写出。设备未确认这些字段前，适配器不得静默省略或改写键名。

## 8. 工程模型与配置文件

### 8.1 工程文件和运行文件

继续使用 JSON，区分两个用途：

1. **保存工程**：保存完整 `EditorDesign`；可以是草稿，也可以带本次成功编译的运行结果。
2. **导出运行配置**：从当前工程重新校验、编译，只写目标设备接受的字段。导出路径与工程路径分开，禁止直接覆盖当前工程。

工程顶层沿用旧综合设计提出的四部分：

| 部分 | 保存内容 |
| --- | --- |
| EditorDesign | 编辑版本、目标设备信息、任务设置、画布、器件、接口和连接，作为编辑的完整依据 |
| LogicEngine / LogicTasks | 可选编译结果或兼容平面缓存；草稿可保留旧缓存，但必须标失效，不用于导出 |
| CompilationInfo | draft/project/ready/stale、编译器版本、目标配置标识、源与运行摘要、来源对应表 |

【现有兼容状态】`project` 表示工程编译通过，不表示设备部署校验通过；`HierarchicalCompilationService.cs:129-145` 在此状态只生成 ProjectDigest，RuntimeDigest 为 null，部署编译成功才设置 ready。`EditorSerializationService.cs:217-239` 识别该状态并写入旧格式 EditorMetadata。读取既有工程（含 Version=1）时保留其来源状态，按新状态模型重新校验，不直接升级为 ready；版本或摘要不符则将缓存标 stale 并保留来源诊断。运行导出／部署始终重新执行目标能力校验和完整编译，不能把 project 或历史 ready 当作当前部署许可。

`EditorDesign.SchemaVersion` 本次建议定为 `2.0.0`，用于区别旧综合文档提出的平面 1.0.0；这是新工程格式版本。`LogicEngine.Version` 继续使用经两端确认的运行协议版本，不能根据编辑版本自动填写。

默认完整工程保存在上位机，设备接收专门导出的运行文件。设备确认能够原样保留 EditorDesign 后，才增加“包含工程的部署文件”选项。仅有运行文件时，可以导入普通平面内容，层级及手工布局无法完整恢复时明确提示；只剩编译辅助节点且无原图的配置按只读执行图打开。

### 8.2 主要数据对象

现有 DTO 位于 Models/Editor/；下表为需对齐的目标契约，不表示全部字段已实现，运行类型与界面对象之间只存 ID 引用：

| 对象 | 关键字段及约束 |
| --- | --- |
| EditorDesignModel | SchemaVersion、DocumentId、TargetRuntimeProfile、Tasks、ID 分配状态 |
| EditorTaskModel | TaskId、Name、Enable、ScanInterval_ms、任务日志设置、RootCanvasId、Canvases、Structures、IntegralStorageBindings |
| EditorCanvasModel | CanvasId、OwnerSubprocessElementId、Elements、Connections、BoundaryPorts、NextBoundaryInputPortId、NextBoundaryOutputPortId、TextDesc、SourceOrder、ViewState |
| ElementSubprocess | IElementModel 基础字段、ChildCanvasId、SubprocessNo、Display；Type=SUBPROCESS |
| BoundaryPortModel | Id、Direction、Kind、Name、Order、数据类型、IsRequired、TransferTarget；属于该子画布对应的图标接口 |
| EditorConnectionModel | ConnectionId、Kind、Role、Source、Target、RoutePoints |
| EditorEndpointModel | NodeKind、ElementId 或 BoundaryCanvasId、Direction、PortRole、可选 PortId；方向可由源/目标推导，边界画布身份不得丢失；统一键见第4.4节 |
| ElementDisplayInfo | SizeMode、Width、Height、FontSize |
| CanvasViewState | Zoom、ScrollX、ScrollY；不参与执行关系 |
| SubprocessEditSession | 工作副本、任务级候选差异、父会话、进入/最近提交基线、接口差异、脏状态和局部历史；不写入工程 |
| RuntimeCompilationResult | 运行任务、运行端口映射、SourceMap、诊断、资源统计及目标版本 |

普通器件仍有自己的 `Inputs/Outputs` 定义；子过程图标的输入、输出由其子画布 `BoundaryPorts` 生成，不能独立编辑两份接口表。`BoundaryPortModel.Direction` 表示相对父图标的方向。同一子画布、同一方向内，数据和控制边界口统一分配唯一ID；两个方向可分别从0开始。

在子画布连接集合中，外部输入通过 `NodeKind=boundary` 作为来源，外部输出通过 boundary 作为目标。这样接口到内部端口的连接仍由同一个 Connections 集合表达，无需额外保存一套容易失配的映射线。

控制边界也使用相同端点形式：入口 boundary → 内部入口，内部正常尾 → 完成 boundary，特殊跳转 → 带 TransferTarget 的 boundary。数据输入 boundary 允许多个内部目标；数据输出 boundary 只有一个内部来源。控制入口目标唯一，完成口可接受多条合法正常路径。

`OwnerSubprocessElementId` 与父图标 `ChildCanvasId` 双向校验。根画布的 Owner 为空；每个非根画布恰好有一个图标拥有。每个图标的父画布可以通过元素所有权索引取得，避免保存多套可矛盾的父指针。Canvases 在任务中平面列出，层级通过 ChildCanvasId 构成树。

器件列表及参数 DTO 可以保留普通 List；绑定到新增列表界面的视图模型使用 ObservableCollection 并转发属性变更。端口提交后触发一次 `PortsChanged` 或结构刷新，重建相关控件和连接；不用全面更换旧 IElementModel 集合签名。

### 8.4 新文件恢复顺序

1. 检查文件大小、编辑版本、层级深度和对象数量限制，读取到临时文档。
2. 通过工厂和类型契约创建器件；恢复参数、完整动态端口、分配计数器和 Display。
3. 建立所有画布、所有权和器件身份索引，检查层级无环、单一归属、子过程编号唯一。
4. 先恢复 BoundaryPorts，再由 Connections 重建当前需要的兼容端口视图。
5. 恢复结构归属、配对、日志引用和文字，检查跨层引用。
6. 根据布局服务建立控件和锚点，最后画线并恢复根视口。
7. 校验编译信息是否对应当前工程和目标。版本变化、摘要不符时将运行缓存置 stale；project 按第8.1节保留来源状态，不自动转 ready。任何历史状态都不能跳过运行导出／部署时的完整校验与编译。
8. 全部加载成功后再切换当前文档。失败保留当前工程，报告文件、层级路径和字段。

系统只恢复根画布为活动层；各子画布视口保留，用户打开时再按保存状态显示。临时编辑会话、鼠标状态、选中视觉及设备运行状态不写入工程。

【拟新增统一读取限制】文件不超过50MiB、根以下16层、每工程10000编辑节点及50000连接、每任务1024画布，宽高请求各不超过20000 DIP。当前读取入口尚未完整实现这些限额，不作为现有安全保证。限额集中在 EditorResourceLimits，受限解析后先迭代检查所有权／深度再递归展开，不靠栈溢出拒绝层级环。超限提示具体值、保留原文件，不截断；工程限额与设备每任务500节点分开校验。

### 8.5 旧文件和旧器件迁移

先识别顶层 EditorDesign 和 LogicTasks[].EditorMetadata.Version=1：两者均为可承载完整设计的工程格式。读取优先顶层设计；若同时存在，须规范化比较，一致才读取，不一致阻止静默选择并提示保留原文件、由用户确认权威版本后另存。只有两者都没有才按纯平面旧格式迁移：

已有 CompilationInfo 或 EditorMetadata 中的 project 按第8.1节保留并重校验，不因能恢复完整设计或存在 ProjectDigest 就转为 ready；迁移成功不代表可部署，必须重新执行目标能力校验和完整编译。

1. 每个旧 LogicTask 建立自己的根画布，任务数、周期和使能保持。旧“组”所产生的任务不自动合并为子过程。
2. 保留旧器件 ID、名称、X/Y、参数、端口和 CompilationSourceOrder；无 Display 时采用新的自动布局。增加常显类型区后外观高度可能增大，坐标和执行关系保持。
3. 从两端连接记录建立诊断；有效输入优先、输入缺失且来源唯一时可兼容恢复。有冲突时列出修复清单，不静默选择多个候选之一。
4. 转为 Connections，固定数据口保留原身份，动态口完整恢复；输入镜像 Value 与连接统一生成。
5. 旧 SWITCH 按分支角色识别 default，保留各 Case 的端口 ID。只调整显示位置，不能把“最后一个输出”机械改号为 0。
6. 旧 SWITCH 的 CaseValue 可无损转换时显式迁移，复杂表达式保留原版本。旧 WHILE 只有五字段不能推断条件／计次模式，由用户确认、标版本并显式输出模式及上限，不能因新设备缺省而改变语义。
7. `ARITHMETIC_INTEGRAL` 与本次 `ALGO_INTEGRAL` 参数、状态方案不同，保留为不同契约。只有显式转换器完成单位、状态和参数映射后才转换。
8. 默认另存新工程，保留源文件；未知类型或未来版本允许只读查看原始内容并诊断，禁止丢节点后报告完整成功。

同步读、异步读、保存回读和克隆共用 `EditorSerializationService`。保留 Newtonsoft.Json 和必要的 TypeNameHandling.Auto；Binder 只接受已注册器件、参数 DTO 和明确历史别名，转换器不能绕过它创建任意 CLR 类型。新格式不再无差别经过“仅保留默认模板条目”的旧升级流程。

### 8.6 工程保存事务

`SaveOperationResult` 明确返回成功、取消、校验失败、写入失败及清理警告，并包含实际提交路径。

1. 在独立候选会话栈协调子层，形成候选根图与编译快照，捕获修订号；磁盘提交前不改真实会话、活动层和各基线，详见第6.7节。
2. 校验工程结构。用户保存草稿时保存诊断和完整原图，旧运行缓存标失效；仅工程编译通过可记录 project，不直接转 ready。生成 ready 必须在独立运行副本上重新完成目标能力校验和完整部署编译。
3. 对固定规则序列化的原图和运行内容分别计算 SHA-256 摘要，记录编译器和目标配置标识。摘要用于检查一致性，传输授权和签名另行处理。
4. 在目标同目录写唯一临时文件，完整写入后刷新并关闭。
5. 用统一读取链回读并对所有任务比较规范模型：Type、完整参数、Inputs／Outputs、SourceOrder、连接、层级、Display、端口高水位及未知扩展字段；不因缺 EditorMetadata 跳过。ready 另查运行目标及摘要，JSON 文本相等只能证明文件内容完整，不能代替模型往返。
6. 原文件存在时原子替换，新文件使用同卷移动。不支持原子替换时保留旧文件并报错，用户可另存新路径。
7. 提交成功后才更新路径及保存检查点。提交后备份清理失败单独告警，不将已完成的提交误报成“原文件未变”。
8. 保存期间若又发生编辑，只标该快照已保存，后续修改继续显示未保存。

新工作区通过 EditorProjectSaveService 保存，成功后更新编译信息、路径和磁盘基线。旧 SaveToFile／CommitSavedCompilation 只保留旧平面兼容，需逐步重定向，禁止新层级计划回写原图。现有回读 JToken.DeepEquals 偏重写出文本，仅有 EditorMetadata 时完整比较 EditorTask，尚须补齐上表规范模型范围。新保存已有 Flush、Replace/Move 严格提交路径；旧 TransactionalConfigSaveService 的 File.Copy fallback 非原子，属于待收口项。稳定序列化保留 Case、端口及 SourceOrder 语义顺序，非语义连接按端点和 ID 排序。

工程和运行导出各自原子提交。导出失败不影响已保存的工程，工程保存成功也不等于设备配置已经下发成功。

## 9. 编译、执行与诊断

### 9.1 从原图到运行配置的步骤

在已有 `Services/ControlFlow/HierarchicalCompilationService` 基础上补齐以下管线，输出独立运行结果：

1. **冻结快照。**保留原始连接及错误证据，新工程不先调用旧一口一源修复去覆盖控制汇合。
2. **检查层级。**校验全部画布身份、唯一所有权、无环、接口方向、结构归属和完整参数。
3. **连接接口。**按子过程图标端口追到 BoundaryPorts 和内部实际端点；数据边界逐层替换，正常控制完成绑定父流程，特殊转移校验所属结构。
4. **展开子过程。**按 SourceOrder 深度展开，去掉图标及边界对象，保留普通器件和控制结构的来源路径；空正常子过程直接连接前后。
5. **检查数据和控制图。**数据依赖无环；控制环必须对应授权循环回边；单入口、分支归属、正常后继和输出定义路径合法。
6. **生成执行关系。**复用并扩展现有 Normalize、Extract、BuildRegions、Linearize 等阶段，计算实际入口、数据依赖前序和后继。
7. **核验运行身份。**普通器件保留源画布 Id，拒绝重复、越界及入口契约冲突；仅辅助节点分配合法空闲 Id，建立方向内端口映射。
8. **运行协议转换。**生成 SwitchPara、linkdev、静态 JUMP、旧 IF 参数和普通 NextID，统一重写所有引用。
9. **最终校验。**检查每个运行节点静态生成一次、数据生产先于消费、合法控制回跳、目标存在、资源预算及目标能力。
10. **输出和定位。**返回运行配置、SourceMap、诊断和资源统计；失败丢弃副本，工程和正式编号不改变。

子过程展开在控制流区域分析之前完成。不能先把各个子图的 NextID 编译好，再按数组拼接。当前实际分支入口有时是目标器件的数据依赖链首项，完整展开后才能确定。

### 9.2 现有编译模块的扩展边界

当前控制提取依赖 Pure_Control 类别及端口标记。新图已有明确数据/控制类别，增加输入适配器，不能把控制汇合和回边传给数据依赖调度。dataControl 连接分别进入两种分析，但运行图统一安排目标执行，不能让数据调度再次追加同一次控制到达的副作用节点。表中连接 Kind 在实现时统一支持data、control、dataControl；数据投影携带原端口，控制投影解析逻辑执行角色。

- IF 保留现有兼容路径，仍检查 IFParaInfo 的真、假目标和实际连线一致性。
- SWITCH 用本次数值算子及 Order 建立描述，允许重叠条件；取消新契约路径中旧字符串查重的硬拒绝。
- 新 WHILE 无数据端口，linkdev 显式模式／上限；入口 SourceElemId 按第7.3节在最终图确定，作为控制元数据单独转换，不套用数据输入检查，也不无条件删除。
- JUMP 作为当前路径终结处理，静态目标有意图地指向后续、回边或合法出口。普通顺序串联不能覆盖 JUMP 目标。
- 循环和提前退出需要识别控制图中的回边及多路径；原来的分支尾自动回控制头规则要与显式 JUMP 去重，避免生成双回跳。
- 同一源给两个分支提供纯数据时，按数据可见性与执行路径检查。当前 UI 中简单禁止 IF 跨分支扇出的前置规则应迁入统一验证器，防止它在编译前挡住合法的新图。

`ControlFlowPlanApplier` 继续服务不新增节点的旧平面计划。层级图、自动桥接及新循环经过 `RuntimeGraphBuilder` 生成单独任务列表，最终验证不要求它与工程图标集合相同。

### 9.3 执行顺序和循环更新

SourceOrder 记录用户创建或明确调整的编译次序，作为等价候选的稳定排序依据，位置和图标大小不参与控制语义。

普通数据链沿用现有输入口顺序与稳定前序规则。编译器保留“同一节点静态只生成一次”和“循环中可以多次执行”两个概念，不能用全局 IsVisited 阻止后续循环重新求值。

新 WHILE 仅条件模式实时读取遥信，计次模式不读。Body 内计算、输出、积分、日志按真实到达执行；必要纯依赖按本次值刷新。有副作用的遥控、写库、保存、积分、打印、延时等须处于明确执行路径，不能隐式拉入刷新链。

循环外可共享纯输入只有在值的读取时机等价时才提升；默认不做改变采样时机的优化。多个正常分支结束后后继只执行一次，SWITCH 无隐含贯穿到下一 Case。

首期不自动复制普通器件来解决不同分支的后继冲突。共享纯节点只有在共同执行前序处求值、采样时机不变且后继唯一时才允许复用；无法证明时给出“共享计算需要在分支内分别放置”的诊断，阻止运行导出。用户可显式复制纯计算链到两条分支。循环内外共享、一次求值后需要两个不同静态 NextID 等情况也按此检查，禁止用任意一个后继覆盖另一个。

### 9.4 运行编号及引用映射

本次循环协议限定目标 ID 0～499，并要求每任务运行节点不超过 500。两个限制分别检查。目标能力可以进一步收紧，不能截断超限节点。

运行引用使用 `(TaskId, RuntimeId)` 识别，普通元件 RuntimeId 保持源画布 Id，不按任务从 0 重编号。现有按全配置 ElementId 建立的编辑所有权索引仍用于原图；运行验证器按任务作用域核验目标。仅辅助节点另取合法空闲 Id，分配规则见第 3.2 节。

固定顺序为任务顺序、层级 SourceOrder、同节点的生成角色顺序；平局再按稳定 ID。禁止把 Dictionary 或 HashSet 的遍历顺序变成编译输出。

先取得依赖调度完成后的真实任务入口。目标 `EntryMode` 的 `arrayFirst` 将真实入口排在序列化列表第一项，不要求其 Id 为 0；`idZero` 则要求实际入口 Id 已为 0，不满足时明确拒绝，不重编号。两项组合时须同时满足；`explicit` 仅在目标显式入口字段契约确认后写入。布局、源输入顺序和元件身份相互独立，普通后继、IF/SWITCH 分支、WHILE/JUMP、数据端口及日志引用仍统一映射并校验。入口规则未知或无法满足时禁止导出，不能静默降级。空任务按目标已确认的禁用/空任务规则输出。

统一引用访问器覆盖：

```text
普通 Id、NextID、Input.SourceElemId/SourcePortId
Output.TargetPorts.ElemID/PortID
IFParaInfo、ControlFlow 分支和 Join/Entry/LoopBack/Exit
SwitchPara 的 default 和 Cases
WHILE 的 ContinueNextID/ExitNextID、JUMP 目标
子过程边界、结构归属、积分存储配对
日志结构化实参及导出的 $器件ID.实际输出端口ID
```

不属于元件引用的实时库号、链路号、寄存器号按各自点位契约处理，不能误当元件 ID 重排。

### 9.5 正常完成和终止示例

父画布为 `A → P001 → Z`，P001 内 `B → SWITCH → C或D → 完成`。

1. 内联后 A 进入 B 的实际依赖入口。
2. SWITCH 命中后进入 C 或 D，各自正常尾到 Z。
3. 修改 P001 名称、图标尺寸或子画布坐标不改变这一轨迹。
4. 若 D 路径显式“结束本轮”，D 的终止目标生成 -1，该路径不执行 Z；图标常显终止标记。
5. 若 P001 在循环体中，某路径声明“继续 W1”，该路径绑定 W1 的授权回边而不经过 Z，正常路径照常经过 Z。

验收必须为该例写独立预期轨迹，检查 Z 的执行次数。只检查数组里出现了全部器件不够。

### 9.6 目标能力和诊断

TargetRuntimeProfile 是本地适配模型，ConfirmedContracts 字符串和本地预设不等于设备已确认。现有 TargetRuntimeProfilePresets 有“本地协议基线、非硬件已联调”预设，须区分本地可编译／测试文件与允许部署。目标 Profile 应保存证据版本、确认范围及安全能力；设备解析、WHILE 预算、日志资源、异常策略未确认时不得部署。未确认新版字段映射时禁止相关运行导出，离线仍可存草稿。

日志容量以第7.1节暂定共享文件方案计算：每个启用链路一份 1024×1040=1,064,960 字节（1.015625 MiB），不按实例叠乘；任务 8 槽及实例 64 条缓存另计。实际结构、上下文和临时空间按已确认目标预算，不以启动文件大小代替最终占用。未知或超限禁止部署；若改实例文件或旧双文件方案，须重算并联调。

循环预算是拟新增安全门槛：已知逐节点成本上界时，在最终运行图顺序求和、互斥取最大、嵌套按次数递推，覆盖 WHILE/JUMP/IF/SWITCH、依赖刷新、重复进入、I/O 与阻塞延时；成本未知就报告未知，不能以扫描周期冒充 WCET。全任务预算只在扫描开始设置，内层及重复进入 WHILE 不重置，逐步检查预算与停止条件。条件模式不以 MaxIterations 替代预算；计次模式遇阻塞节点或总成本不可证明也不得安全部署。扫描周期仅用于调度约束比较。

新增运行版本和 RequiredCapabilities 只有在设备确实检查它们时才有拒绝保护。旧设备只读已知字段时，上位机必须先门控，不能靠向文件里多写一个能力字段保证安全。

每条诊断增加任务、画布路径、器件、端口、关联连接和运行编号。例如：

```text
任务“功率调节” / P001“预处理” / P004“分流” / SWITCH E23
Case 端口 7 的目标已被删除。请重新连接该分支或移除该 Case。
```

点击诊断依次打开所需子画布并选中器件；若当前层有未提交修改，先经过会话关闭协调，不能为了定位丢弃用户工作。

### 11.4 设备联调验收

- SWITCH 用已知数值验证算子边界、重叠顺序、默认和本轮结束；循环中再次到达不死循环失控。
- WHILE 按两种模式分别验收：计次模式验证 `MaxIterations` 到数自动退出、上游再进入时计数清零、回跳继续累加；条件模式验证遥信变化、初次为假、体内回跳、提前退出、长迭代、短扫描周期、嵌套和停止/热加载。条件模式必须验证设备确有全任务步数/时间预算与停止检查，否则禁止部署。
- 积分先核对运行 `Params[0].Name="IntegralPara"`，再使用恒定数值和实际时长验证首轮、门限、ms/s 等价、任务抖动、NaN/Inf、读写失败；系统时钟改变不改变单调时间累计。对 10 分钟阈值前／恰好／超过分别采证，确认实际计时基准与内部比较，不预设 `>=`；超过时不跨段积分，随后短间隔恢复累计。另测实时库被外部改写后重新同步基值。
- 积分已累计到非零后执行 Reset，独立记录 Reset 前后库值、内存累计、累计输出及后续时间基线轨迹，确认不清库、不清累计；Reset 后首次处理和是否补面积按确认契约判定。
- 积分配套先恢复再累计；验证持久化恢复、归档延迟及两个器件执行顺序。存储先写标记后断电的损失窗口如实记录。
- SAVE_DATA 验证首次偏移、重启不重复、历史优先、删标记、关初值、透传、周期/变化、完整文件及其他键保留。两种后续策略均关闭时，分别测有历史恢复、无历史建档、满足条件的初始偏移及数值／标记写入和首次恢复失败重试，不按“完全不写”判定。分别测省略字段按0、新建显式1/1/1、显式0往返不变；恢复写库失败下周期重试，标记写失败下次启动重试；关初值或InitVal=0不读写标记。普通变化量在死区下／等于／超过处采证，同时命中及保存成功／失败后的计时、变化基线分别确认；“或”触发与严格大于仅为拟定规则，取得设备证据后再定通过标准，YX固定0.1阈值另测。
