## 2. 开工前的 1 分钟环境自检

每次启动新一轮开发前，在配置端仓库根目录先跑一次契约自检，确认 Wave 0 基线完好（加 `-B` 避免产生 `__pycache__`）：

```powershell
cd D:/repo/dfe/LinuxApp/visualconfig
python -B contracts/vcl/v1/validate_contracts.py
```

看到输出 `OK: validated 51 opcodes, 3 valid sample packages, 6 malformed sample packages, 22 golden vectors (9 executed on reference VM).` 且退出码为 `0`，即可开始派活。

## 3. 两种日常落地用法

根据你手头的工具形态，在下面两种方式中任选其一（也可以混合使用）。

### 方式 A：由强模型当“主控智能体”自动统筹（推荐）

如果你的编程环境支持主控自动拉起子会话或工作流节点，你只需要开一个**强模型窗口（Tier-0 主控）**，把下面这段提示词直接发给它启动 **Wave 1**：

```text
请作为 Tier-0 主控编排者，严格按以下文档推进 VCL P2 阶段 Wave 1：
1. 阅读 D:/repo/booknote/articles/可视化编程规约C语言表达能力编码实现与智能体调度计划.md（重点看第 1、4、8～13 章）；
2. 先运行 python -B D:/repo/dfe/LinuxApp/visualconfig/contracts/vcl/v1/validate_contracts.py 确认 Wave 0 基线通过；
3. 初始化状态文件 D:/repo/dfe/LinuxApp/visualconfig/temp/vcl-orchestrator/state.json；
4. 按第 12 章的 4 个 Wave 1 任务包（T2.01_T2.02、T2.03、T2.06、T2.10），按“Layer 1 静态前缀 -> Layer 2 最小契约 -> Layer 3 任务单”顺序，分别开启独立全新子窗口并行实现（严禁修改 .csproj / Program.cs / logic_visual_programming.c）；
5. 全部返回后，由你按第 11、13 章执行 L1 越界检查、统一登记 .csproj 与 Program.cs、执行 MSBuild 与 GCC 编译及单测；
6. 通过集成屏障 B1 后更新 state.json，并主动输出“新主控窗口冷启动指令”暂停，等我开新窗口进入 Wave 2。
```

### 方式 B：手工把任务单分发给不同轻量模型窗口（如 Gemini Hydrogen）

如果你想手工切换不同轻量模型或不同账号窗口来节省成本，按以下 **4 步循环**推进：

#### 第 1 步：1 个任务开 1 个全新轻量模型窗口（并行跑 Wave 1）

绝对不要在同一个轻量模型窗口里连续做两个任务。同时新开 **4 个独立轻量模型窗口**（它们修改的文件互不重叠，可并行执行）：

- **窗口 1（`T2.01_T2.02` 源工程与摘要）**
- **窗口 2（`T2.03` 诊断与词法分析器）**
- **窗口 3（`T2.06` 脚本签名与端口迁移）**
- **窗口 4（`T2.10` C99 受限 JSON 容器解码器）**

每个窗口里的提示词必须严格按 **三层 KV-Cache 友好顺序** 粘贴：

1. **开头（Layer 1 静态前缀，逐字节原样粘贴，不要加时间戳或编号）**：
   - C# 窗口（1/2/3）：粘贴 `D:/repo/dfe/LinuxApp/visualconfig/contracts/vcl/v1/prompts/prefix_csharp_v1.txt`；
   - C99 窗口（4）：粘贴 `D:/repo/dfe/LinuxApp/visualconfig/contracts/vcl/v1/prompts/prefix_c99_v1.txt`。
2. **中间（Layer 2 最小只读契约）**：
   - 只提供对应 YAML 任务单中 `read_only_context` 列出的那 2～5 个文件（如只读某几行就明确标出行号范围，不灌全文）。
3. **末尾（Layer 3 任务单）**：
   - 粘贴《编码实现与智能体调度计划》第 12 章里对应的那一份 YAML 任务包。

#### 第 2 步：切回强模型窗口做“集成屏障 B1 验收”

4 个轻量模型写完文件后，**不要让轻量模型自己去改 `.csproj`、`Program.cs` 或 `.cproject`**。切到你的**主控强模型窗口**，发送：

```text
Wave 1 的 4 个任务（T2.01_T2.02、T2.03、T2.06、T2.10）已由轻量模型写入磁盘。
请按 D:/repo/booknote/articles/可视化编程规约C语言表达能力编码实现与智能体调度计划.md 第 11 章和第 13 章执行屏障 B1：
1. 执行 L1 检查：确认 git status / git diff 未越界修改禁止文件、无 C# 8+ 语法、无临时文件泄露到 temp/ 外；
2. 统一登记新增 .cs 文件到 LogicEngineConfigTool.csproj 和 LogicEngineConfigTool.RegressionTests.csproj，并在 Program.cs 注册 --vcl-wave1-only（拒绝未知 --vcl-* 参数）；
3. 执行 MSBuild Debug 编译、--vcl-wave1-only 单测，以及 gcc -std=c99 -Wall -Wextra -Werror -pedantic 编译并运行 test_vcl_package；
4. 若有任务失败，为失败任务提取最前 1～3 条真实错误（不超过 60 行），给出定点修复消息或 handoff 换窗交接单；
5. 若全部通过，更新 D:/repo/dfe/LinuxApp/visualconfig/temp/vcl-orchestrator/state.json，并输出 Wave 2 的新主控窗口冷启动指令。
```

#### 第 3 步：遇到报错时的修复与“防降智”换窗规则

| 情况 | 正确做法 | 错误做法（避免踩坑） |
| --- | --- | --- |
| **第 1 次编译或单测失败**（窗口还干净，未超 45% 上下文） | 保持原轻量模型窗口的 Layer 1 + Layer 2 **完全不动**，只在对话末尾粘贴主控截取的前 1～3 条精准错误（≤ 60 行）让其定点修复 | 把几百行完整 MSBuild 日志贴进去，或者重排前面的提示词导致 KV-Cache 失效 |
| **第 2 次仍失败**，或小模型出现“重复犯同错 / 改 A 坏 B / 写 `TODO` 省略代码 / 乱编字段名” | **立刻关掉旧窗口！** 让主控把现状浓缩成 `temp/vcl-orchestrator/handoff/<task-id>_clean_restart.md`，新开一个**中等模型（Tier-1）窗口**接手（或拆成两个更小任务给新轻量窗口） | 在已经脏掉的旧窗口里继续第 3、4 轮追问和争辩 |
| **C# 与 C 两端各自单测通过，但对拍结果不一致** | 交给 **Tier-0 主控**对照 `contracts/vcl/v1/` 裁决哪端违约，再定点修违约端 | 让小模型私自修改黄金测试向量去迁就错误代码 |

#### 第 4 步：过完屏障，主控自己也主动换新窗口

每完成一个集成屏障（`B1 → B2 → B3 → B4 → G2`），主控都会把最新状态写入 `D:/repo/dfe/LinuxApp/visualconfig/temp/vcl-orchestrator/state.json`。此时**关掉旧的主控窗口**，开一个全新的强模型窗口，粘贴以下冷启动模板进入下一波次：

```text
请从磁盘恢复 VCL 编排进度，不要依赖历史聊天：
1. 读取 D:/repo/dfe/LinuxApp/visualconfig/temp/vcl-orchestrator/state.json；
2. 读取 D:/repo/booknote/articles/可视化编程规约C语言表达能力编码实现与智能体调度计划.md 第 9～11 章；
3. 按 state.json 中的 next_action 生成下一波次任务包并继续执行。
```

## 4. 整套流程的推进节奏

推荐按“**先打通最小闭环，再横向铺开**”的节奏走，不要一次同时铺 20 个任务：

1. **第一里程碑（优先跑通 P2 / G2）**：依次走完 `Wave 1 → B1 → Wave 2 → B2 → Wave 3 → B3 → Wave 4 → B4 → Wave 5 → G2`。只要 `P2-01`～`P2-09` 在 C# 参考解释器和 C VM 宿主上 100% 跑平，就说明整套轻量模型协作流水线完全顺畅。
2. **第二里程碑（P3 / G3）**：复制同样节奏，先更新 Wave 0 契约到 P3，再分波次派发数组、无递归函数、循环和图形桥接。
3. **第三里程碑（P4 / P5）**：进入设备侧快照、功能块、非阻塞输出与热加载生命周期，其中涉及并发锁与掉电恢复的核心任务（`T4.05`、`T5.01`～`T5.04`）固定分配给 Tier-1 中等模型，外围模块和单测继续交给 Tier-2 轻量模型。

## 5. 日常操作必须守住的 5 条底线

1. **绝不把整份大文档喂给轻量模型**：轻量模型只看 `prefix_*.txt` + 3～5 个只读契约文件 + 自己的 YAML 任务单（初始输入压在 12K tokens 内）。
2. **绝不让轻量模型直接改共享文件**：`LogicEngineConfigTool.csproj`、`LogicEngineConfigTool.RegressionTests.csproj`、`Program.cs`、`VisualEditorViewModel.cs`、`logic_visual_programming.c`、`.cproject` 永远只由主控在集成屏障统一修改。
3. **绝不复用脏窗口**：1 个任务 = 1 个新 Worker 窗口；1 个 Wave = 1 个新主控窗口；一见降智信号立刻换新窗，不跟小模型在旧窗口拉锯。
4. **任何契约改动先跑自检**：需要增删 opcode、错误码或黄金向量时，先改 `contracts/vcl/v1/` 并跑通 `python -B contracts/vcl/v1/validate_contracts.py`，再派发双端修改。
5. **所有临时状态与编译产物留在 `temp/` 内**：编排状态放 `visualconfig/temp/vcl-orchestrator/`，任务临时文件放 `visualconfig/temp/<task-id>/`，C 宿主编译产物放 `visualconfig/temp/vcl_c_host/`，不污染代码目录。
