这种现象通常不是 Modbus 协议本身的问题，而是 **Modbus Slave 的配置或通信模式导致它没有严格按从站地址过滤报文**。

先区分两种情况：

- Modbus RTU 报文：第 1 个字节是从站地址，随后第 2 个字节才是功能码。
- 例如：`02 03 00 00 00 02 CRC`  
  这里 `02` 是从站地址，`03` 是功能码，不是两个从站地址。

正常情况下，如果 Modbus Slave 只配置为从站 ID `1`，收到从站地址为 `02`、`03`、`04` 的 RTU 报文时，应该不响应。

最常见原因如下。

### 1. 实际使用的是 Modbus TCP，并勾选了 Ignore Unit ID

如果连接类型是 **Modbus TCP/IP**，报文中的从站地址实际上叫 **Unit ID**。Modbus Slave 的 TCP 设置中有一个 **IgnoreUnit ID** 选项。勾选后，软件会忽略请求中的 Unit ID，因此即使主站发送 `02`、`03`、`04`，软件也可能都应答。官方手册明确说明，该选项会忽略 Unit ID。[1]

处理方法：

1. 按 `F3` 打开连接设置。
2. 确认连接类型。
3. 如果是 Modbus TCP/IP，取消勾选 **IgnoreUnit ID**。
4. 重新连接测试。

### 2. 打开了多个 Modbus Slave 窗口

Modbus Slave 支持在多个窗口中模拟多个从站，每个窗口都可以配置不同的 Slave ID。官方说明它可以模拟最多 100 个从站窗口，而且每个窗口可以代表相同或不同的从站节点。[1,2]

因此需要检查：

- 是否打开了多个数据窗口；
- 其他窗口的 Slave ID 是否被设置成了 `2`、`3`、`4`；
- 是否有窗口被最小化或隐藏；
- 是否加载了以前保存的工作区，里面包含多个从站定义。

可以关闭所有窗口，只保留一个窗口，再把它设置为 Slave ID `1` 进行测试。

### 3. 把“功能码”误认为“从站地址”

例如主站发送：

```text
01 03 00 00 00 02 CRC
```

含义是：

- `01`：从站地址 1
- `03`：读保持寄存器
- `00 00`：起始寄存器地址
- `00 02`：读取 2 个寄存器

如果你看到报文中有 `02`、`03`、`04`，它们可能分别是：

- 读取数量；
- 功能码；
- 寄存器地址的一部分；

不一定代表从站地址。建议打开软件的 **Communication Traffic**，只看每帧报文的第一个字节。

### 4. 使用的是 RTU Over TCP，而不是标准 RTU

Modbus Slave 支持以下几种连接方式：

- Serial；
- Modbus TCP/IP；
- Modbus UDP/IP；
- Modbus RTU Over TCP/IP；
- Modbus RTU Over UDP/IP。[1]

如果你使用的是 **RTU Over TCP**，要确认报文格式和软件的解释方式。它不是标准 Modbus TCP，Unit ID 的处理方式可能与标准 TCP 不同。

### 5. 实际应答并不是 Modbus Slave 发出的

如果你通过串口抓包发现：

```text
主站请求：02 03 ...
软件应答：01 03 ...
```

那么软件可能只是收到了报文，但真正的应答来自：

- RS-485 总线上的其他设备；
- USB-RS485 转换器或网关；
- 另一个正在运行的 Modbus Slave 实例；
- 同一串口被其他程序占用；
- 总线上存在地址为 `2`、`3`、`4` 的真实设备。

如果应答帧的第一个字节也是 `02`、`03`、`04`，才说明对应地址的设备或模拟窗口确实在应答。

### 建议的排查顺序

1. 确认使用的是 **Serial/RTU** 还是 **Modbus TCP**。
2. 查看每个请求帧的第一个字节是否真的是从站地址。
3. 如果是 TCP，取消 **IgnoreUnit ID**。
4. 关闭其他 Modbus Slave 数据窗口。
5. 只保留一个 Slave ID 为 `1` 的窗口。
6. 断开总线上其他设备，只连接电脑和转换器。
7. 用串口抓包工具确认应答帧的第一个字节。

如果是在 **标准 Modbus RTU、只有一个窗口、Slave ID=1、总线上没有其他设备** 的条件下，软件仍然对地址 `02`、`03`、`04` 返回有效应答，那么重点检查是否实际上启用了多个实例，或者主站发送的“02、03、04”并不是从站地址。Modbus Slave 的 Slave ID 设置范围是 1～255，而标准 Modbus 规范通常使用 1～247。[1]

**PLC Address (base 1)** 的意思是：使用 **从 1 开始的 PLC 地址编号**，而不是从 0 开始。

以保持寄存器为例：

| PLC 地址（Base 1） | Modbus 协议中的偏移量 |
|---|---:|
| 40001 | 0 |
| 40002 | 1 |
| 40003 | 2 |

也就是说：

- PLC 地址 `40001` 对应 Modbus 报文中的起始地址 `0`
- PLC 地址 `40002` 对应报文中的起始地址 `1`
- PLC 地址 `40010` 对应报文中的起始地址 `9`

例如，主站要读取 PLC 地址 `40001` 的 2 个保持寄存器：

```text
01 03 00 00 00 02 CRC
```

其中：

- `01`：从站地址
- `03`：读取保持寄存器
- `00 00`：协议地址偏移量 0，也就是 PLC 地址 40001
- `00 02`：读取 2 个寄存器

如果软件选择 **base 0**，则通常会把第一个寄存器显示为地址 `0`；选择 **base 1**，则显示为地址 `1`。因此主站、PLC 和 Modbus Slave 必须使用一致的地址基准，否则很容易出现“读到相邻寄存器”或“地址偏移一位”的问题。

简单记忆：

> **Base 1：第一个寄存器地址是 1。**  
> **Base 0：第一个寄存器地址是 0。**

另外，不要把 `40001` 中的 `4` 和地址 `0001` 混为一谈：`4` 通常表示保持寄存器类型，而实际协议发送的地址偏移量是 `0`。

`PLC Address (base 1)` 只影响软件界面显示方式：

| Modbus Slave 显示方式 | 第 1 个寄存器显示为 | 报文中的地址 |
|---|---:|---:|
| PLC Address base 0 | 0 | `00 00` |
| PLC Address base 1 | 1 | `00 00` |

所以即使界面显示为地址 `1`，底层报文仍然可能使用地址偏移量 `0`。

- **自己拼原始 Modbus 报文**：第 1 个寄存器使用 `00 00`。
- **使用支持 40001 地址格式的驱动**：填写 `40001`。
- **使用要求零基地址的驱动**：填写 `0`。
- **使用要求一基地址的驱动**：填写 `1`。
