# AI电子设计大模型

有，而且已经从“论文演示”进入了部分商业化阶段。不过要区分：

- **真正的电子设计大模型/Agent**：能理解需求、调用 EDA 工具、运行仿真、分析日志并迭代。
- **传统 EDA 中加入 AI/机器学习优化**：例如自动布局布线、参数优化、PPA 优化，并不一定是大语言模型。
- **面向工程师的 Copilot**：查数据手册、生成 HDL/SPICE、解释错误、生成脚本等。

目前还没有一个成熟产品可以完全替代电子工程师，尤其是高速、高功率、射频、可靠性和 EMC 认证环节。

## 1. 芯片设计：发展最快，已有较成熟商业产品

### Cadence

Cadence 的 AI 产品线包括：

- **Cerebrus**：利用机器学习/强化学习自动探索 RTL、综合、布局布线等参数，优化 PPA。
- **Verisium AI**：面向验证、调试、覆盖率分析和故障定位。
- **Cadence.AI / Agentic AI**：逐渐加入基于自然语言和 Agent 的设计流程编排。
- AI 也覆盖部分模拟、射频、封装和 PCB 流程。

Cerebrus 更准确地说是“AI 驱动的 EDA 优化器”，而不是 ChatGPT 式的通用大模型。  
官网：<https://www.cadence.com/en_US/home/ai/overview.html>

### Synopsys

Synopsys 的 **Synopsys.ai** 覆盖：

- RTL 生成和修改辅助；
- 综合、布局布线和 PPA 优化；
- 验证计划、覆盖率收敛、调试；
- EDA 工具日志和设计数据分析；
- Agent 编排多个 EDA 工具。

Synopsys 还在推进所谓 **Agentic EDA** 和 **AgentEngineer**，目标是让 Agent 自主执行“理解需求—修改设计—运行工具—分析结果—继续优化”的闭环。

官网：<https://www.synopsys.com/ai.html>

### Siemens EDA

Siemens 正在把生成式 AI 和 Agent 引入：

- **Questa**：验证和调试；
- **Calibre**：物理验证；
- **Catapult**：高层次综合；
- **Xpedition**：PCB 设计；
- **Tessent**：测试；
- **Veloce**：仿真和硬件加速验证。

Siemens 在 2025 DAC 展示了面向半导体和 PCB 的 EDA AI 系统，重点是企业内部知识、工具调用和设计数据安全。

官网：<https://www.siemens.com/en-gb/company/electronic-design-automation/trending-technologies/eda-ai/>

### 研究型芯片大模型

学术界和大厂研究中，已经有多类模型：

- **ChipNeMo**：面向芯片设计企业语料进行训练，用于工程问答、脚本生成、文档和验证辅助。
- **RTL 代码大模型**：根据自然语言生成 Verilog/SystemVerilog。
- **RTL 修复 Agent**：根据编译、仿真、形式验证结果自动修改 RTL。
- **EDA Agent**：调用 Verilog 编译器、仿真器、综合工具、形式验证工具。
- **模拟电路设计模型**：进行拓扑生成、器件尺寸优化和仿真迭代。
- **布局布线优化模型**：主要是强化学习、图神经网络和代理模型，不一定使用 LLM。

这类系统的关键不是“能不能生成一段 Verilog”，而是能否：

1. 理解完整设计约束；
2. 调用真实 EDA 工具；
3. 自动发现错误；
4. 通过仿真和形式验证；
5. 保证时序、功耗、面积和可制造性。

目前第 2～5 步仍然需要较多工程约束和人工审核。

## 2. 电路设计和 SPICE 仿真：已经有产品，但自动化程度不一

目前 AI 可以辅助：

- 根据文字需求生成电路框图；
- 推荐元器件；
- 读取数据手册；
- 生成 SPICE 网表；
- 生成仿真脚本；
- 自动调整电阻、电容、晶体管参数；
- 根据仿真波形寻找问题；
- 进行模拟电路参数优化；
- 检查电源完整性、信号完整性和设计规则。

但“从一句话直接生成可生产的模拟电路”仍然不可靠。原因包括：

- 元器件真实参数和供应情况复杂；
- 温度、容差、老化、寄生参数影响很大；
- 稳定性、环路补偿、噪声和 EMC 不是简单文本推理问题；
- 必须通过 SPICE、Corner、Monte Carlo 等验证。

更实际的方案是让 LLM 充当**电路工程助手**，调用 ngspice、LTspice、Spectre、HSPICE 或商业 EDA 工具，而不是单独依赖大模型输出。

## 3. PCB 原理图和布局布线：已有比较直观的 AI Agent

### Flux.ai

Flux 是目前比较典型的云端 AI PCB 平台，AI 可以辅助：

- 根据自然语言生成原理图；
- 查询和理解数据手册；
- 推荐器件；
- 连接网络；
- 生成 PCB 初始布局；
- 自动布线；
- 审查设计；
- 回答设计问题。

官网：<https://www.flux.ai/>

它更接近“带 AI Agent 的电子设计平台”，适合原型设计、教育、开发板和中小型项目。但复杂高速板、射频板和量产板仍然需要人工完成关键布局。

### Quilter

Quilter 采用物理约束驱动的 AI，主要用于：

- PCB 元件布局；
- PCB 自动布线；
- 根据规则和约束生成多个候选方案；
- 与 Altium、Cadence、Xpedition 等流程衔接。

官网：<https://www.quilter.ai/>

它的特点不是聊天，而是“物理驱动的布局布线优化”。

### CELUS

CELUS 主要面向：

- 功能需求到电路模块；
- 器件选型；
- 原理图生成；
- PCB 设计前期自动化；
- 设计复用。

它比较适合模块化、标准化产品，而不是高度定制的复杂高速系统。

### Altium、Siemens Xpedition 等

主流 PCB EDA 厂商也在加入：

- AI 设计助手；
- 设计规则解释；
- 器件和封装搜索；
- 原理图检查；
- 元件布局和布线优化；
- 企业历史设计复用；
- 设计数据问答。

不过在 PCB 领域，当前最成熟的 AI 仍然是：

> 自动布局、自动布线、规则检查、设计复用和搜索推荐

而不是通过一个大模型完全自动完成 PCB。

## 4. 电磁仿真、EMI/EMC：有 AI，但“自动通过 EMC 实验”还比较远

### 已经可以应用 AI 的方向

AI 在电磁领域主要用于：

- 天线参数优化；
- PCB 走线和层叠优化；
- EMI 噪声预测；
- 屏蔽结构优化；
- 滤波器参数优化；
- 电磁仿真代理模型；
- 从大量仿真结果中建立快速预测模型；
- 识别辐射峰值与潜在源头；
- 优化接地、回流路径和电源完整性。

例如，Ansys、CST、Simcenter、Cadence 等平台都在使用机器学习、代理模型、参数优化或自动设计空间探索。

Ansys EMI/EMC：  
<https://ansys.synopsys.com/applications/emi-emc>

SIMULIA 电磁兼容仿真：  
<https://www.3ds.com/products/simulia/electromagnetic-simulation/compatibility>

### EMC 实验检测中的 AI

在实际 EMC 实验室里，AI 更可能用来：

- 自动控制测试设备；
- 自动执行测试序列；
- 自动识别频谱峰值；
- 自动生成测试报告；
- 对比历史测试数据；
- 判断异常波形；
- 对测试失败进行初步归因；
- 推荐滤波、屏蔽、接地或布局修改；
- 建立“设计参数—测试结果”的预测模型。

但是，AI 目前通常不能替代：

- 法规规定的测试设备；
- 校准和计量要求；
- 标准规定的测试环境；
- 认证机构的判定；
- 工程师对整改措施的最终确认。

换句话说：

> AI 可以帮助预测“可能过不了 EMC”，也可以帮助找原因，但不能仅凭大模型结论证明产品已经符合 CISPR、IEC、FCC、CE、GB 等规范。

EMC 领域更常见的是“机器学习 + 电磁仿真 + 实验数据”，而不是纯 LLM。

## 5. 一个比较实际的电子设计 Agent 架构

如果要自己搭建，典型架构会是：

```text
用户需求
   ↓
LLM / 多模态大模型
   ↓
需求解析、约束提取、设计计划
   ↓
工具调用 Agent
   ├── 器件数据库 / 供应链
   ├── 数据手册解析
   ├── KiCad / Altium / Cadence / Siemens
   ├── SPICE 仿真
   ├── RTL 编译和仿真
   ├── 综合、时序和布局布线
   ├── SI/PI/EMC 仿真
   └── 测试仪器和实验室数据
   ↓
结果分析、错误修复、设计迭代
   ↓
工程师审核和签核
```

比较可靠的 Agent 不应该直接“相信模型”，而应采用：

- 工具调用；
- 结构化约束；
- 编译/仿真/DRC/ERC 作为反馈；
- 自动生成验证报告；
- 每次修改保留 diff；
- 关键结果可追溯；
- 工程师最终批准。

## 6. 目前不同方向的成熟度

| 方向 | 当前成熟度 | AI 主要作用 |
|---|---:|---|
| 芯片 PPA 优化 | 较高 | 强化学习、设计空间搜索 |
| 芯片验证和调试 | 较高 | 日志分析、覆盖率、故障定位 |
| RTL 生成 | 中等 | 代码生成和修改辅助 |
| 模拟 IC 自动设计 | 中等 | 参数优化、拓扑探索 |
| PCB 器件布局 | 中等偏高 | 约束驱动自动布局 |
| PCB 自动布线 | 中等 | 生成候选布线方案 |
| 电路原理图生成 | 中等 | 模块和器件级辅助 |
| SPICE 自动设计 | 中等 | 参数搜索和仿真闭环 |
| SI/PI 分析 | 中等 | 代理模型和优化 |
| EMI/EMC 预测 | 初步到中等 | 仿真加速、风险预测 |
| EMC 实验自动判定 | 初步 | 数据整理、峰值识别、报告生成 |
| 完全自动量产设计 | 较低 | 仍需资深工程师把关 |

## 7. 对“有没有大模型 Agent”的结论

**有，但主要是“LLM + 专业 EDA 工具 + 优化算法 + 仿真验证”的组合，不是一个单独的大模型包打天下。**

目前最接近商业化“电子设计 Agent”的几类产品是：

1. **Cadence.AI / Cerebrus / Verisium**：芯片和系统级 EDA；
2. **Synopsys.ai / Agentic EDA**：芯片设计、验证和工具流程自动化；
3. **Siemens EDA AI**：芯片、验证和 PCB；
4. **Flux.ai**：带 AI Agent 的原理图和 PCB 平台；
5. **Quilter**：物理驱动的 PCB 布局布线；
6. **CELUS**：电路模块、器件和原理图设计辅助；
7. **Ansys、CST、Simcenter、Cadence 等**：电磁仿真和优化中的 AI；
8. 各类研究型 **RTL Agent、模拟电路 Agent、EMC 预测模型**。

如果按“现在最适合实际落地”的顺序，我会建议：

- **芯片团队**：先从验证日志分析、脚本生成、回归测试 Agent 开始；
- **嵌入式硬件团队**：先从数据手册问答、器件选型、原理图审查开始；
- **PCB 团队**：先用 AI 做布局候选、布线候选和 DRC/ERC 检查；
- **EMC 团队**：先做测试数据分析、失败归因和仿真代理模型；
- **企业级部署**：让 Agent 调用已有 EDA 工具，而不是替换 EDA 工具。
