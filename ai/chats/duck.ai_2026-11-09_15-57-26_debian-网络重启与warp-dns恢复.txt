Debian 13 常用的重启网络服务命令是：

```bash
sudo systemctl restart networking
```

如果系统使用 **NetworkManager**，则使用：

```bash
sudo systemctl restart NetworkManager
```

查看网络服务状态：

```bash
systemctl status networking
# 或
systemctl status NetworkManager
```

如果只是重启某个网卡，例如 `ens33`：

```bash
sudo ip link set ens33 down
sudo ip link set ens33 up
```

也可以使用 `ifupdown`：

```bash
sudo ifdown ens33 && sudo ifup ens33
```

远程 SSH 操作时，重启网络可能会导致连接中断。 Debian 13 默认常见的是 `systemd-networkd`、NetworkManager 或传统 `ifupdown`，可先用下面命令确认：

```bash
systemctl is-active networking NetworkManager systemd-networkd
```

这通常不是 `networking` 服务本身的问题，而是 **WARP 断开后没有正确恢复 DNS 配置**。WARP 在连接时可能会把 `/etc/resolv.conf` 指向自己的本地 DNS 代理，例如 `127.0.2.2`、`127.0.2.3`；如果断开时恢复失败，系统仍然会把 DNS 请求发到已经停止的 WARP DNS 代理，所以域名无法解析。Cloudflare 也将这类问题归因于本地 DNS 配置、第三方 DNS 服务或 DNS 代理冲突。[1,2]

先判断是“只有 DNS 坏了”，还是“整个网络都断了：

```bash
ping -c 3 1.1.1.1
getent hosts www.baidu.com
cat /etc/resolv.conf
resolvectl status
```

如果 `ping 1.1.1.1` 能通，但 `getent hosts www.baidu.com` 失败，基本可以确定是 DNS 问题。

## 直接恢复 DNS

先重启 WARP 服务，并重新执行断开：

```bash
sudo systemctl restart warp-svc
warp-cli disconnect
```

然后查看：

```bash
cat /etc/resolv.conf
```

如果里面仍然是类似下面的内容：

```text
nameserver 127.0.2.2
nameserver 127.0.2.3
```

可以临时改成公共 DNS：

```bash
sudo rm -f /etc/resolv.conf

printf '%s\n' \
'nameserver 223.5.5.5' \
'nameserver 1.1.1.1' \
'nameserver 8.8.8.8' | sudo tee /etc/resolv.conf
```

测试：

```bash
getent hosts www.baidu.com
ping -c 3 www.baidu.com
```

## 如果 Debian 13 使用 systemd-resolved

如果你希望由 `systemd-resolved` 管理 DNS，可以执行：

```bash
sudo systemctl enable --now systemd-resolved

sudo rm -f /etc/resolv.conf
sudo ln -s /run/systemd/resolve/stub-resolv.conf /etc/resolv.conf

sudo systemctl restart systemd-resolved
sudo resolvectl flush-caches
```

再测试：

```bash
resolvectl status
resolvectl query www.baidu.com
```

Cloudflare 针对 Linux 上 WARP 与 `systemd-resolved` 的 DNS 连接问题，也建议检查 `systemd-resolved` 配置并重启该服务，而不是只重启 `networking`。[1,3]

## 如果连 IP 也无法访问

如果下面命令也失败：

```bash
ping -c 3 1.1.1.1
```

那就不只是 DNS，可能是 WARP 断开后残留了路由或防火墙规则。尝试：

```bash
warp-cli disconnect
sudo systemctl restart warp-svc
sudo systemctl restart NetworkManager 2>/dev/null || true
sudo systemctl restart networking 2>/dev/null || true
```

然后检查默认路由：

```bash
ip route
```

正常情况下应能看到类似：

```text
default via 192.168.1.1 dev eth0
```

或者：

```text
default via 192.168.1.1 dev enp1s0
```

如果没有 `default` 路由，可以先重新连接网络接口：

```bash
nmcli device status
sudo nmcli networking off
sudo nmcli networking on
```

如果机器使用的是 `systemd-networkd`，则执行：

```bash
sudo systemctl restart systemd-networkd
```

## 建议检查 WARP 日志

```bash
warp-cli status
sudo journalctl -u warp-svc -n 100 --no-pager
```

重点查看是否出现：

```text
DNSLookupFailed
DNS connectivity check failed
resolv.conf
Failed to restore DNS
```

另外，`ping www.baidu.com` 失败只能说明 DNS 解析失败或 ICMP 不通，最好同时使用：

```bash
curl -I https://www.baidu.com
```

最可能适合你当前情况的恢复顺序是：

```bash
warp-cli disconnect
sudo systemctl restart warp-svc
sudo rm -f /etc/resolv.conf
printf '%s\n' 'nameserver 223.5.5.5' 'nameserver 1.1.1.1' | sudo tee /etc/resolv.conf
getent hosts www.baidu.com
```
