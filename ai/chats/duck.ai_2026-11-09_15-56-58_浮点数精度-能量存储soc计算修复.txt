## 一、先区分十进制数和二进制浮点数

人类通常使用十进制：

```text
0.15 = 15 / 100 = 3 / 20
```

但计算机中的 `float` 和 `double` 使用的是二进制科学计数法。

二进制小数的形式类似：

```text
1.xxxxx × 2^n
```

很多十进制小数无法用有限位二进制精确表示。

例如：

```text
0.5 = 0.1₂
0.25 = 0.01₂
0.75 = 0.11₂
```

这些数可以精确表示。

但是：

```text
0.1
0.15
0.2
0.3
```

通常不能用有限位二进制精确表示。

### 0.15 为什么不能精确表示

将 `0.15` 乘以 2，依次取整数部分：

```text
0.15 × 2 = 0.30  → 0
0.30 × 2 = 0.60  → 0
0.60 × 2 = 1.20  → 1
0.20 × 2 = 0.40  → 0
0.40 × 2 = 0.80  → 0
0.80 × 2 = 1.60  → 1
0.60 × 2 = 1.20  → 1
...
```

得到类似：

```text
0.001001100110011001100110...₂
```

这个二进制小数会无限循环，因此计算机只能截取有限位，保存一个最接近的值。

## 二、IEEE 754 浮点数结构

### 1. `float` 结构

通常情况下，C 语言中的 `float` 使用 IEEE 754 单精度格式：

```text
总长度：32 位
```

结构如下：

| 字段 | 位数 | 含义 |
|---|---:|---|
| 符号位 | 1 位 | 0 表示正数，1 表示负数 |
| 指数位 | 8 位 | 保存指数，偏移量为 127 |
| 尾数位 | 23 位 | 保存有效数字的小数部分 |

示意：

```text
┌────┬──────────┬───────────────────────┐
│符号│  指数 8位 │      尾数 23位        │
└────┴──────────┴───────────────────────┘
```

对于规格化的正数：

\[
value = (-1)^s \times \left(1+\frac{fraction}{2^{23}}\right)
\times 2^{E-127}
\]

其中：

- \(s\)：符号位；
- \(E\)：指数位对应的整数；
- `fraction`：尾数整数值；
- 127：单精度指数偏移量。

`float` 大约有：

```text
7 位十进制有效数字
```

---

### 2. `double` 结构

通常情况下，C 语言中的 `double` 使用 IEEE 754 双精度格式：

```text
总长度：64 位
```

结构如下：

| 字段 | 位数 | 含义 |
|---|---:|---|
| 符号位 | 1 位 | 0 表示正数，1 表示负数 |
| 指数位 | 11 位 | 偏移量为 1023 |
| 尾数位 | 52 位 | 保存有效数字的小数部分 |

示意：

```text
┌────┬─────────────┬───────────────────────────────────────┐
│符号│  指数 11位  │              尾数 52位                │
└────┴─────────────┴───────────────────────────────────────┘
```

对于规格化的正数：

\[
value = (-1)^s \times \left(1+\frac{fraction}{2^{52}}\right)
\times 2^{E-1023}
\]

`double` 大约有：

```text
15～16 位十进制有效数字
```

因此，`double` 比 `float` 精确很多，但它仍然不能精确表示所有十进制小数。

## 九、最终比较为什么必然得到真

最终比较器的阈值：


15.0 这个数可以被 `float` 和 `double` 精确表示，因为：

```text
15 = 1111₂
```

它是一个整数，没有二进制小数部分。

比较器实际拿到的左值接近：

```text
15.000000953674316
```

右值是：

```text
15.000000000000000
```

所以实际比较是：

```text
15.000000953674316 > 15.000000000000000
```

结果当然是：

```text
true
```

日志中的：

```text
大于比较器输入:15.000001>15.000000
结果:1.000000
```

从计算机角度看是正确的，并不是比较器判断错误。

错误发生在业务语义层面：

```text
业务上认为它们都代表 15%
```

但浮点数实际比较的是：

```text
15.000000953674316
```

和：

```text
15.000000000000000
```

## 十一、为什么日志中看起来像是“同一个结果有两个值”

日志中出现：

```text

除法器结果:0.15000000596046447754
```

这两个值不是同一个变量在同一时刻的同一种类型。

它们分别代表：

```text

0.14999999999999999445
```

以及：

```text
float 转换后的结果：
0.15000000596046447754
```

建议日志中明确标注类型，例如：

```c
printf("double result = %.20f\n", double_result);
printf("float  result = %.20f\n", (double)float_result);
```

或者：

```c
printf("double result = %a\n", double_result);
printf("float  result = %a\n", (double)float_result);
```

不要只打印：

```text
result = ...
```

否则容易误以为是同一个数据在不同位置产生了两个结果。

## 十二、建议用 `%a` 检查浮点数

C 语言的 `%a` 可以以十六进制浮点格式输出数值：

```c
double d = 75.0 / 500.0;
float f = (float)d;

printf("d = %.20f, %a\n", d, d);
printf("f = %.20f, %a\n", (double)f, (double)f);
```

结果可能类似：

```text
d = 0.14999999999999999445, 0x1.3333333333333p-3
f = 0.15000000596046447754, 0x1.333334p-3
```

其中：

```text
0x1.3333333333333p-3
```

表示：

\[
1.3333333333333_{16} \times 2^{-3}
\]

`%a` 对排查浮点格式、类型转换和隐含精度非常有帮助。

## 十三、代码中如何确认是否发生了转换

可以对关键变量进行类型隔离：

```c
double div_result;
float  float_result;
double restored_result;

div_result = input1 / input2;
float_result = (float)div_result;
restored_result = (double)float_result;

printf("div_result      = %.20f\n", div_result);
printf("float_result    = %.20f\n", (double)float_result);
printf("restored_result = %.20f\n", restored_result);
```

预期：

```text
div_result      = 0.14999999999999999445
float_result    = 0.15000000596046447754
restored_result = 0.15000000596046447754
```

如果想检查字节，可以使用 `memcpy`，避免违反严格别名规则：

```c
#include <stdint.h>
#include <string.h>
#include <stdio.h>

static uint32_t float_bits(float value)
{
    uint32_t bits;
    memcpy(&bits, &value, sizeof(bits));
    return bits;
}

static uint64_t double_bits(double value)
{
    uint64_t bits;
    memcpy(&bits, &value, sizeof(bits));
    return bits;
}

int main(void)
{
    double d = 75.0 / 500.0;
    float f = (float)d;

    printf("double bits = 0x%016llX\n",
           (unsigned long long)double_bits(d));

    printf("float bits  = 0x%08X\n",
           float_bits(f));

    return 0;
}
```

对于当前案例，应该观察到类似：

```text
double bits = 0x3FC3333333333333
float bits  = 0x3E19999A
```

## 十四、系统设计中应该如何处理

### 方案一：实时库全链路使用 `double`

如果系统确实要求计算链路保存双精度，应该保证以下各层全部使用 `double`：

```c
double
```

包括：

- 元件输入值；
- 元件输出值；
- 元件内部临时变量；
- 输出接口参数；
- 实时库字段；
- 实时库写入函数；
- 实时库读取函数；
- 中间缓存；
- 数据结构成员；
- 日志函数参数。

例如：

```c
typedef struct {
    double value;
} RtdbValue;
```

接口：

```c
void RtdbWriteDouble(int no, double value);
double RtdbReadDouble(int no);
```

不能只是把某一个计算元件改成 `double`，但在输出元件中又写成：

```c
float val;
```

否则数据一旦经过该元件，仍然会降回单精度。

---

### 方案二：实时库继续使用 `float`，比较器进行量化

如果实时库必须使用 `float`，就不要要求普通浮点数承担严格的业务边界判断。

可以在比较器中按照配置精度量化：

```c
#include <math.h>
#include <stdint.h>

static int64_t quantize(double value, int32_t scale)
{
    return (int64_t)llround(value * (double)scale);
}

static int compare_greater(double value,
                           double threshold,
                           int32_t scale)
{
    int64_t value_q = quantize(value, scale);
    int64_t limit_q = quantize(threshold, scale);

    return value_q > limit_q;
}
```

保留 4 位小数：

```c
int result = compare_greater(value, threshold, 10000);
```

当前数据：

```text
15.000000953674316 × 10000 ≈ 150000
15.000000000000000 × 10000 = 150000
```

转换为整数后：

```text
150000 > 150000
```

结果为假。

其他比较符也应在量化后执行：

```c
value_q >  limit_q
value_q >= limit_q
value_q <  limit_q
value_q <= limit_q
value_q == limit_q
```

比较器的业务含义应明确为：

> 按配置精度量化后比较，而不是按原始浮点位逐位比较。

---

### 方案三：控制策略使用整数交叉相乘

对于当前储能 SOC 场景，最可靠的方式是避免构造浮点百分比。

已知：

```text
当前电量 = 75
额定电量 = 500
阈值 = 15%
```

判断：

```text
75 / 500 × 100 > 15
```

可以变换为：

```text
75 × 100 > 500 × 15
```

代码：

```c
#include <stdint.h>
#include <stdbool.h>

bool soc_greater_than_15(int32_t current,
                         int32_t rated)
{
    if (rated <= 0) {
        return false;
    }

    return (int64_t)current * 100 >
           (int64_t)rated * 15;
}
```

对于本例：

```text
75 × 100 = 7500
500 × 15 = 7500
```

因此：

```text
7500 > 7500
```

为假。

如果是“大于等于 15%”：

```c
return (int64_t)current * 100 >=
       (int64_t)rated * 15;
```

这种方式完全不依赖 `float` 和 `double` 的小数表示。

## 十五、为什么乘法前后的输出值不能用于精确控制判断

浮点数适合：

- 测量值；
- 连续计算；
- 趋势分析；
- 显示；
- 工程量换算。

但对于以下逻辑需要谨慎：

```c
value == threshold
value > threshold
value < threshold
```

尤其是：

```text
除法 → 乘法 → 多次存储 → 多次类型转换 → 阈值比较
```

因为每一次 `float` 存储都可能发生舍入。

对于储能充放电策略，阈值判断往往属于状态机控制，因此应优先使用：

```text
整数比较
定点数比较
量化后比较
带滞环比较
```

而不是直接依赖原始浮点值。

---

## 十六、关于“保留小数位”的正确理解

例如设置：

```text
精度：4 位小数
```

不建议简单写成：

```c
(int)(value * 10000)
```

因为这是截断，可能带来方向性误差。

更推荐：

```c
int64_t quantized = llround(value * 10000.0);
```

例如：

```text
15.000000953674316 → 150000
15.000050000000000 → 150001
```

然后比较量化后的整数：

```c
if (value_q > threshold_q) {
    ...
}
```

阈值也必须进行同样的量化：

```c
value_q     = llround(value * scale);
threshold_q = llround(threshold * scale);
```

不能只量化输入值而不量化常量。

## 十七、最终结论

本次日志可以总结为以下几个结论。

### 1. 75 和 500 没有问题

它们是整数，可以被 `float` 和 `double` 精确表示：

```text
75.0
500.0
```

### 2. `double` 除法结果是正常的

除法器内部原始字节：

```text
33 33 33 33 33 33 C3 3F
```

对应：

```text
double 0.14999999999999999445
```

这是 `double` 表示 `0.15` 的正常结果。

### 3. 主要误差在元件 49 输出时产生

原始 `double`：

```text
0.14999999999999999445
```

转为 `float`：

```text
0.15000000596046447754
```

日志中的：

```text
9A 99 19 3E
```

证明了这次转换。

### 4. 元件 51 使用了已经被 `float` 舍入的值

实际计算是：

```text
0.15000000596046447754 × 100
```

而不是：

```text
0.14999999999999999445 × 100
```

所以结果为：

```text
15.00000059604644775391
```

### 5. 元件 52 又发生了一次 `double` 到 `float` 转换

```text
15.00000059604644775391
        ↓
15.00000095367431640625
```

### 6. 比较器本身执行正确

它比较的是：

```text
15.000000953674316 > 15.000000000000000
```

结果为真是符合 IEEE 754 数值规则的。

### 7. 真正的问题是数据类型和业务精度不匹配

系统期望的是：

```text
15.0000% 和 15.0000% 视为相等
```

但代码执行的是：

```text
15.000000953674316 和 15.0 的原始浮点比较
```

因此后续设计应在以下方案中选择一种：

```text
全链路使用 double；
或比较器内部按配置精度量化；
或使用整数/定点数；
或对 SOC 阈值直接使用交叉相乘。
```

对于当前储能策略，最推荐：

```text
采集和显示可以使用 float；
控制决策使用整数、定点数或交叉相乘；
不要让浮点百分比直接参与关键阈值判断。
```
