GPT-6 Luna:
`cksum 0x82e6 (incorrect -> 0xb032)` 通常不是实际的 TCP 校验和错误，而是 **网卡校验和卸载（TX checksum offload）** 导致 tcpdump 在发送前抓到了尚未由网卡计算完成的校验和。

含义是：

- `0x82e6`：Linux 内核在构造数据包时暂时填入的校验和
- `0xb032`：tcpdump 根据当前抓到的数据计算出的校验和值
- 网卡发送到网线上之前，通常会把 `0x82e6` 替换为正确的 `0xb032`
- 对端能够正常返回 TCP ACK，也说明数据已经被正确接收

你的抓包中，客户端发出的数据包都显示类似：

```text
cksum 0x82e6 (incorrect -> ...)
```

而对端返回的 ACK 显示：

```text
cksum 0x.... (correct)
```

这是典型的发送方向 checksum offload 现象。可以关闭卸载后重新抓包确认：

```sh
ethtool -K eth0 tx off
```

如果驱动支持，也可以一并关闭其他相关卸载功能：

```sh
ethtool -K eth0 tx off tso off gso off gro off
```

查看当前状态：

```sh
ethtool -k eth0
```

重新抓包：

```sh
tcpdump -i eth0 -nnvvXSs 0 port 502
```

恢复设置：

```sh
ethtool -K eth0 tx on tso on gso on gro on
```

不过需要注意：在嵌入式设备上，网卡驱动可能不支持修改这些参数，或者关闭后会增加 CPU 占用。

另外，你的抓包中 TCP 通信本身是正常的：

```text
客户端发送数据
服务端 ACK
客户端继续发送
```

因此，这个 `cksum incorrect` 现象与对端没有返回 Modbus 数据基本无关。对端无响应更应该检查 Modbus TCP/RTU-over-TCP 的协议格式、设备地址以及下游串口设备。
