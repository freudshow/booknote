你这台 GMKtec M5 Pro 上，所谓“厂商推送固件更新”通常不是 GMKtec 直接向你的主机建立连接并主动推送，而是下面这种**客户端主动查询**的流程。

## 典型流程

1. **固件提供方制作更新包**

   对于 BIOS/UEFI，通常由电脑厂商或主板厂商制作；对于 SSD，则可能由 SSD 厂商制作。更新包会包含：

   - 固件版本号；
   - 适用的设备型号；
   - 设备唯一识别信息，如 GUID/硬件匹配 ID；
   - 更新说明；
   - 数字签名。

2. **发布到固件服务**

   支持 Linux 的厂商可以把固件上传到 Linux Vendor Firmware Service，也就是 LVFS。LVFS 对更新包进行处理并生成带签名的元数据，供 `fwupd` 客户端查询。[1,2]

   但厂商也可能只在自己的支持网站、Windows Update 或 BIOS 内置更新机制中发布固件。**没有发布到 LVFS 的固件，`fwupdmgr` 就看不到。**

3. **你的 Debian 系统刷新元数据**

   `fwupd` 或桌面软件定期从 LVFS 下载最新的“固件目录元数据”。你手动执行的：

   ```bash
   sudo fwupdmgr refresh --force
   ```

   就是强制执行这一步。它下载的主要是“有哪些设备、有哪些版本、适用于哪些型号”的目录信息，不一定马上下载固件本体。

4. **本机进行匹配**

   `fwupd` 读取本机硬件信息，并拿设备识别 ID 与目录中的适用设备进行匹配。

   你的机器识别信息大致包括：

   ```text
   HostProduct: GMKtec M5 Pro
   HostBaseboardProduct: GMKtec
   HostBiosVersion: M5 Pro 1.03
   WDC WDS500G1B0C-00S6U0
   ```

   如果目录中有适用于这些硬件的更高版本，就会显示为可更新；没有匹配项，或者当前版本已经不低于目录版本，就显示：

   ```text
   Devices with no available firmware updates
   ```

5. **通知用户**

   如果系统的 `fwupd` 检查服务、桌面软件或登录提示脚本发现有更新，就可能显示：

   ```text
   1 个设备有可升级的固件。
   ```

   这实际上是**你的电脑检查到目录中有更新后的本地通知**，而不是 GMKtec 实时连接你的电脑发送通知。

6. **用户确认并下载更新包**

   你执行：

   ```bash
   sudo fwupdmgr update
   ```

   后，`fwupd` 会下载适用于本机的更新包，验证其签名和适用设备，然后安装。能够在线更新的设备会直接更新；BIOS/UEFI 等通常会先暂存到 EFI 系统分区，然后重启，由 UEFI 在启动前完成更新。[2,3]

7. **可选的更新结果报告**

   更新完成后，`fwupdmgr` 可能询问是否上传更新成功或失败的报告。这个报告用于帮助固件维护者统计更新成功率，不是获取更新的必要步骤。`fwupd` 文档将这种报告描述为可选功能。[3]

## 对你这次具体情况

你的流程实际是：

```text
刷新 LVFS 元数据
        ↓
发现 UEFI dbx 有新版本
        ↓
下载安装并更新
        ↓
UEFI dbx: 20260402 → 20260707
        ↓
更新成功
```

这次更新的 `UEFI dbx` **不是 GMKtec M5 Pro BIOS 更新**，也不是 WDC SSD 固件更新，而是 Secure Boot 的撤销列表更新。你的 BIOS 仍然是：

```text
M5 Pro 1.03
```

并且输出显示：

```text
System Firmware: no available firmware updates
WDC WDS500G1B0C-00S6U0: no available firmware updates
```

所以，目前可以理解为：

- GMKtec 没有通过 LVFS 向你的这台机器提供新的 BIOS；
- WDC 没有提供可匹配的 SSD 固件；
- LVFS 提供了新的 UEFI `dbx`；
- Debian 的 `fwupd` 发现并安装了这个更新。

还需要注意，`fwupdmgr` 的更新范围不是“电脑厂商所有固件的完整目录”。如果 GMKtec 只在官网发布 BIOS，而没有将其发布到 LVFS，那么你需要通过 GMKtec 官网或 BIOS 自身的更新功能检查；`fwupdmgr` 显示“没有更新”并不绝对等于“厂商官网也没有更新”。

你这类“随机死机、重启失效”，在你这台 **GMKtec M5 Pro + Ryzen 7 5700U + 自行安装两条内存和 SSD** 的组合上，应该先按**硬件稳定性**排查，而不是先怀疑 Debian。

优先级建议是：

1. 内存兼容性或内存条本身故障；
2. BIOS/内存参数或电源管理问题；
3. SSD、NVMe 控制器或 SSD 接触问题；
4. 散热或电源适配器问题；
5. Linux 内核、显卡或 ACPI 电源管理问题。

这类迷你主机的 CPU 集成显卡也使用系统内存，因此内存不稳定时，可能表现为桌面死机、浏览器崩溃、磁盘报错，甚至完全无法重启。相关 M5 Pro 用户资料显示，该机使用 Ryzen 7 5700U，且实际安装的内存频率和内存条组合会影响稳定性；有测试使用单条 DDR4-3200 内存运行正常，但这不能证明你的两条内存组合一定兼容。[1,2]

## 第一优先：只使用一条内存测试

先完全关机、拔掉电源，打开机器：

1. 拔下其中一条内存；
2. 只保留一条 16 GB；
3. 确认内存完全插到底，两侧卡扣都扣紧；
4. 连续使用一段时间，观察是否还死机；
5. 再换另一条单独测试；
6. 如果两条单独都稳定，再把两条一起装回测试。

建议记录：

| 测试方式 | 结果 |
|---|---|
| 内存 A 单独使用 | 是否死机 |
| 内存 B 单独使用 | 是否死机 |
| A+B 同时使用 | 是否死机 |
| A+B 交换插槽 | 是否死机 |

如果单条稳定、两条一起死机，重点就是：

- 两条内存不是同一套 kit；
- 芯片颗粒或单双 Rank 不兼容；
- BIOS 对两条内存的训练不稳定；
- 两条内存虽然容量相同，但 SPD 参数不同；
- 机器在双通道下无法稳定运行。

在 BIOS 中先恢复默认设置，关闭任何 `XMP`、超频、增强性能或非默认 UMA 显存设置。内存最好是：

```text
DDR4 SO-DIMM
3200 MT/s
1.2 V
JEDEC 标准参数
```

暂时不要追求性能，稳定比双通道更重要。即使厂商标称支持 32 GB，也不代表任意两根 16 GB 内存都能稳定运行。

## 第二优先：运行长时间内存测试

不要只测试几分钟。建议至少测试一晚，最好完成 4～8 个 pass。

可以在 Debian 中安装：

```bash
sudo apt update
sudo apt install memtest86+
```

然后重启，在 GRUB 菜单选择内存测试项目。

也可以使用独立的 MemTest86 或 Memtest86+ U 盘启动。测试时：

- 先只插内存 A；
- 再只插内存 B；
- 最后测试 A+B。

**只要出现一个 error，就不能认为内存稳定。** 即使 Debian 平时能启动，也不能说明内存没问题。对于集成显卡系统，内存错误尤其容易表现为随机死机。

## 第三优先：检查 SSD 和 NVMe 日志

你的 SSD 是：

```text
WDC WDS500G1B0C-00S6U0
```

虽然 `fwupdmgr` 没有发现它有固件更新，但仍应检查健康状态和内核错误。

安装工具：

```bash
sudo apt install nvme-cli smartmontools
```

查看设备名称：

```bash
lsblk -o NAME,MODEL,SERIAL,SIZE,TYPE,FSTYPE,MOUNTPOINTS
```

如果系统盘是 `/dev/nvme0n1`，执行：

```bash
sudo nvme smart-log /dev/nvme0
sudo smartctl -a /dev/nvme0n1
```

重点观察：

```text
critical_warning
media_errors
num_err_log_entries
unsafe_shutdowns
error information log entries
temperature
```

查看当前启动前一次的内核日志：

```bash
sudo journalctl -b -1 -k --no-pager
```

筛选内存、NVMe、PCIe、GPU 和 ACPI 错误：

```bash
sudo journalctl -b -1 -k --no-pager | \
grep -Ei 'nvme|pcie|aer|amdgpu|gpu|mce|edac|hardware error|watchdog|acpi|error|failed'
```

冻结后强制关机，再启动时，用 `-b -1` 查看上一次启动的日志是正确方向；不过如果是突然掉电、硬件完全锁死或内核 panic，日志可能来不及写入。类似诊断通常也是先查看上一次启动的 kernel journal。[3,4]

如果看到类似：

```text
nvme timeout
I/O error
controller reset
AER: Corrected error
AER: Uncorrected error
amdgpu ring timeout
MCE
hardware error
```

就能进一步缩小范围。

## 第四优先：检查散热和电源

你的机器使用 Ryzen 7 5700U，M5 Pro 的高性能模式可能使温度和功耗明显上升；相关实测资料提到该型号在较高 TDP 模式下温度会明显升高。[1]

安装传感器：

```bash
sudo apt install lm-sensors stress-ng
sudo sensors-detect
sensors
```

观察空闲和负载温度：

```bash
watch -n 2 sensors
```

可先把 BIOS 的性能模式设置为：

```text
Balanced
```

暂时不要使用：

```text
Performance
35W
Turbo/增强性能
```

做压力测试时要逐项测试，不要一开始同时压 CPU、内存和 SSD：

```bash
stress-ng --cpu 8 --timeout 10m --metrics-brief
```

内存测试：

```bash
stress-ng --vm 2 --vm-bytes 70% --timeout 10m --metrics-brief
```

SSD 测试前务必备份数据，不建议直接进行破坏性写入测试。

同时检查：

- 使用原装或规格足够的电源适配器；
- DC 插头是否松动；
- 机器底部进风口是否被遮挡；
- 是否放在软布、床面或狭小空间；
- 是否接了质量较差的 USB-C 扩展坞、USB Hub 或外接设备。

排查期间可以只保留：

- 电源；
- HDMI/DP 显示器；
- 键盘；
- 有线网络。

拔掉 USB Hub、移动硬盘、无线接收器、蓝牙设备等，排除外设导致的 USB/电源问题。

## 第五优先：更新或切换 Debian 内核

你现在使用的是：

```text
6.12.107+deb13-amd64
```

先确保系统完全更新：

```bash
sudo apt update
sudo apt full-upgrade
```

然后查看是否有其他已安装内核：

```bash
dpkg -l 'linux-image*' | grep '^ii'
```

重启时进入 GRUB 的：

```text
Advanced options for Debian
```

尝试旧版本内核。如果旧内核稳定、新内核不稳定，才比较像内核或驱动回归问题。

如果是桌面画面卡死但 SSH 仍能登录，问题可能偏向图形栈；如果 SSH 也无法登录、键盘指示灯不响应，则更像内存、主板、供电、固件或内核级锁死。

## “重启失效”时的安全重启

如果只是桌面无响应，但键盘仍有反应，可以启用 Magic SysRq：

```bash
echo 'kernel.sysrq = 1' | sudo tee /etc/sysctl.d/99-sysrq.conf
sudo sysctl --system
```

死机时尝试：

```text
Alt + PrintScreen + R
Alt + PrintScreen + E
Alt + PrintScreen + I
Alt + PrintScreen + S
Alt + PrintScreen + U
Alt + PrintScreen + B
```

也就是 `REISUB`，每个字母之间间隔一两秒。它可以尝试先恢复键盘、结束进程、同步磁盘、重新挂载文件系统，然后重启。若连 `Caps Lock` 指示灯都不响应，通常说明系统已经完全锁死，此方法也可能无效。

## 建议你按这个最短路线执行

1. 备份重要数据；
2. BIOS 恢复默认设置，性能改为 Balanced；
3. 只插一根内存，运行一天；
4. 换另一根内存，再运行一天；
5. 两根一起运行 Memtest86+ 一整晚；
6. 检查 NVMe SMART 和上一次启动日志；
7. 拔掉所有不必要 USB 设备；
8. 如果仍然死机，再测试其他内核或另一套 Linux；
9. 如果 Windows 和 Debian 都会死机，基本应向 GMKtec 要求硬件检修或更换；
10. 如果只有 Debian 死机，再集中排查内核、显卡、睡眠和 ACPI 电源管理。

就你目前的情况，**最应该先做的是“两根内存分别单条测试 + Memtest86+ 长测”**。因为系统是准系统，你自行安装了内存，而“随机死机并且重启失效”最常见、也最容易验证的原因就是内存兼容性或内存本身不稳定。
